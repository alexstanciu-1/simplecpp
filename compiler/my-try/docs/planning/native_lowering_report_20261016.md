## Native boundary

The compiler is rebuilt at O2 through the existing portable-PHP converter and legacy
S2S (`--no-stan` policy). The experiment driver consumes `request.json`, selects
application optimization and writes reports through `CPP_Lowering_Report::encode`.
This validates the native API, not a new production native CLI argument parser.
The PHP CLI retains its documented report arguments. New source/object membership and
report header visibility are supplied by the experiment's native build recipe;
there is no generated-C++ source patch.

One compiler-source correction was needed: the report had widened a declaration to
`collected_name` before calling `qualified_name`, which is declared by
`collected_definition`. PHP dispatched to the concrete method; native compilation
correctly rejected the widened static type. The source now unwraps the known optional
`collected_definition` into a required typed local. This changes no report content.

There were three native build attempts: initial report compilation failure; corrected
report compiled but driver linking failed because the harness omitted program-entry
emission; final build with the generator's program-entry option enabled. The second
correction is harness-only. Original failure logs are retained alongside the success.
The existing broad legacy compiler declaration inventory caused the first and final attempts to
recompile many compiler objects; this is not an application invalidation measurement.

## Validation

All six native executions pass: reports disabled/enabled at O0, O1 and O2.
Each produces the same 292 accounting artifacts as its corresponding previous
initialization-header checkpoint. Enabling reports leaves artifact transport identical.
Both compact and detailed report objects match PHP at each optimization level (six
report comparisons). The report inventories 292 artifacts and 931 retained fragments.
All 216 authored source hashes (215 compiler files plus the experiment driver) match
the native build identity. The focused PHP report suite also passes after the fix.

No accounting runtime or full application benchmark was repeated: generated C++ is
byte-identical to the earlier validated checkpoint. This is bounded native reporting
proof, not a broad compiler regression or new incremental/MT validation.

## Correlation with saved Clang timings

No new application compilation performance benchmark is run here. Correlation uses
the [initialization-header checkpoint](initialization_headers_20261016.md), candidate
variant `outlined` (meaning split initialization headers), three full builds per level,
Ninja eight jobs and Mold eight threads on dev002. Every correlated generated artifact
must match that checkpoint. Individual-unit medians are across those three full-build
observations and include parallel contention; they are not isolated Clang timings.
Previously recorded isolated frontend/backend traces are reported separately.

counts are direct emitted includes, including runtime/callable headers; they are
