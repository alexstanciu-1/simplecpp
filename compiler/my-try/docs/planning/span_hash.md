Doc Status: supporting

## Contract and owners

The [runtime contract](../../../../specs/compiler_support_runtime_contract.md)
owns the approved semantics. Each source buffer owns a distinct state; checked
spans observe it weakly. Release, destruction, move-from and replacement retire
that state. Move assignment also retires the destination's previous state. Copies
of buffers remain independent; copies of spans share the observed lifetime.
Default/expired spans reject even length queries. Self-assignment is a no-op.
Builder append copies bytes before returning. No general borrow checker or
concurrent access contract is introduced. Internal C++ views remain synchronous
borrows and must not survive invalidation.

The source module now has four value types and twenty callable bindings. Its
strings dependency enables builder span append; strings registers the two string
hash helpers. Actual-owner binding uses existing readonly-reference preparation.
Source and builder provider types use existing `concrete_boundary` recipes to
keep template headers out of prelowered application units. No compiler algorithm,
metadata registry or runtime-operation bridge was added.

Stable hashes use FNV-1a64 over exact unsigned bytes, offset 14695981039346656037,
prime 1099511628211, modulo 2^64. Hex helpers return sixteen lowercase digits.
Persisted namespaces must change to `stable_hash_u64:fnv1a64:v2:<16hex>`; the native
versioned-key helper constructs it. Old unversioned/v1 entries cannot be v2 hits.
Hash-table hashing and SHA-256 native build keys are unchanged.

The tracked bin/compiler/runtime/generator consumer audit found provider adapters,
symbol declarations and metadata, but no live persisted stable-helper consumer.
Historical generated compiler/cache artifacts remain untouched. External consumers
must invalidate old namespaces; this repository cannot migrate their storage.
The previous empty/abc/bcd goldens were `1d4483df7b541425`, `d3bed96780249ab5`,
`bbd3bfcaaf9c53d5`; the replacements are `cbf29ce484222325`, `e71fa2190541574b`,
`003f3219133dae62`. Native goldens and the strict expected-output sidecar changed;
original PHS fixtures remain intact.

## Verification

`tests/span_hash.py` passed **13 tasks** (0.14–11.43 seconds) using the shared
12-slot runner on dev002:

- native lifetime tests, also under ASan/UBSan: owner destruction, release, copies,
  replacement, move construction/assignment, empty spans, bounds and binary bytes;
- ten default-prelowered published programs: three strict fixture adaptations,
  release/replacement/destruction errors, independent buffer copies, ordered
  offset/length evaluation and builder-copy survival, and exact uint64 outputs
  from string and span hashes;
- seven successful program builds reuse every object without linking on warm runs;
- retained no-op/edit/fresh output and five rejection/repair cycles, including
  temporary owner, readonly mutation, wrong offset type and the two wider gaps below.

`tests/span_hash_regressions.py` passed **nine tasks** (0.14–7.32 seconds):
stable-hash, builder and binary-codec native regressions; source, memory, builder
and runtime-type PHP checks; and 72 independently calculated Python FNV goldens
under Clang and GCC, each executable run twice. Inputs cover empty/ASCII, embedded
NUL, high bytes, UTF-8, every byte and generated byte sequences. Both compilers
use libstdc++; libc++ was unavailable, so this is not a second-standard-library
execution proof. The specified algorithm and independent oracle replace reliance
on implementation-defined host hashes.

Default prelowering was never disabled for the new source acceptance/recovery
suite. Existing PHP metadata regressions retain their historical ordinary-output
mode and are supplementary. PHP CLI fallback was used because CLI/FPM versions
differ. Native compilation ran on dev002, not WSL; no compiler native rebuild,
PCH run or full matrix was performed.

The first run exposed missing provider concrete-boundary flags; those are repaired.
The first three runs also preserve diagnostic-expectation mistakes corrected by
checking exit 1 and stderr `byte_span_to_string`. They are not runtime failures.

The legacy buffer/hash fixtures require replacing comment type annotations with
strict declarations. The hash fixture additionally compares equivalent hexadecimal
helpers because canonical uint64 equality remains unsupported. Separate source
probes verify both uint64 helper values exactly; this does not close wider fixed-width
operator support. Explicit `move($buffer)` still rejects because source move is
restricted to unique ownership. Native tests verify runtime buffer moves directly.
Neither wider gap is hidden by the fixture adaptations or counted as repaired.

Optional source-module activation is proved through the existing compiler catalog
API; this is not a claim of new project-manifest module selection support. Extreme
4-GiB line/column representability, wider borrowed views and concurrency remain
separate. No hashing, Result or generic count capability is implied for byte_span.
