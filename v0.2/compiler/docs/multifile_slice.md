# Multifile executable slice

Doc Status: supporting

The [entry contract](../../../specs/compiler_entry_v0_2.md) owns the bounded semantics.
One explicitly selected entry supplies the executable's exit value. Secondary
sources may now also contain [void function definitions](functions_slice.md), callable
from any explicitly listed source. Other declaration kinds and top-level execution
ordering remain outside this slice.

## Run the example

After building the default runtime, run from the repository root:

```sh
php v0.2/compiler/main.php program v0.2/compiler/examples/multifile main.scpp v0.2/build/clang/native-layout/facts.json v0.2/build/multifile-slice php main.scpp cpp support.cpp.scpp js support.js.scpp
```

Arguments are source root, selected relative entry, target facts, output directory,
then flavor/relative-path pairs. Membership is explicit; extensions do not select
flavors. Paths must be canonical relative paths within the source root. Missing
entry membership, duplicate logical paths and aliases resolving to the same source
path are rejected.

Execution is sequential. There are no `--mt` or `--serial` selectors; use ordinary
64-bit PHP 8.5+. See [execution guidance](execution.md).

Build exactly the manifest's translation units:

```sh
python3 - <<'PY'
import json
import subprocess
from pathlib import Path
out = Path('v0.2/build/multifile-slice')
manifest = json.loads((out / 'manifest.json').read_text())
subprocess.run(['clang++', '-std=c++23', '-stdlib=libc++',
    '-I', 'v0.2/runtime/generated/public',
    *[str(out / path) for path in manifest['translation_units']],
    'v0.2/build/clang/libscpp_runtime.a', '-o', str(out / 'program')], check=True)
assert subprocess.run([str(out / 'program')]).returncode == 8
PY
```

`manifest.json` maps readable source paths to stable SHA-256-derived unit names.
Each source has a unit; `entry.cpp` supplies the sole `main` and calls the selected
entry body. Comment-only sources produce comment-only units. Root relocation and
inventory reordering preserve generated bytes. This naming stability is not yet
incremental reuse: each invocation processes and republishes all sources.

## Owners and donor findings

- `01_prepare_inputs/program.php`: explicit membership and path validation.
- `compiler/program.php`: source-local read/tokenize/parse/collect jobs, followed
  by whole-program preparation after every frontend result succeeds.
- `04_analyze/prepare/program.php`: whole-program entry selection and admission;
  `prepared_entry` retains the existing single-entry facts.
- `05_backend/cpp/program.php`: stable unit identities and complete rendered output.
- `05_backend/cpp/bundle.php`: inventory-based publication and obsolete-unit cleanup.
- `host/program.php`: CLI arguments and presentation.

The donor's `04_analyze/prepare/program.php` separates entry selection from file
identity and rejects non-entry executable statements. Its C++ artifacts and
implementation groups establish source-owned units and one-pass grouping. We retain
those concepts without importing dependency subscriptions or scheduler machinery.
The donor publication protocol supplies a useful eventual recovery model; its
locking/journaling infrastructure is deferred here.

## Verified checks

- [x] Each flavor can supply the selected entry; mixed-flavor bundles build and exit 8.
- [x] Switching the selected entry changes execution (tested with exit 9).
- [x] Same-basename sources receive distinct units; reordered/relocated inputs produce identical bytes.
- [x] Invalid secondary syntax or executable statements fail before publication.
- [x] Failure preserves existing output and creates no new output directory.
- [x] Missing entry, duplicate membership and invalid relative paths are rejected.
- [x] Source removal retires its old unit; re-addition restores it.
- [x] Unrelated output is preserved and excluded from the link list; unowned collisions fail.
- [x] Program preparation retains collected identities; emission requires prepared program facts.
- [x] In-memory checks cover 10, 100 and 1000 secondary sources without introducing retained global state.

## Deliberate debt and next slices

1. Basic incremental compilation: define invalidation and reusable per-file results
   with focused unchanged/change/add/remove proofs. No timestamps, caches or reuse
   are implemented now.
2. Declaration preparation: add actual contracts and classified prerequisites,
   with dependency ordering reviewed when those declarations are implemented.
   The current pipeline is sequential; publication stays coordinator-owned.

Richer declarations, cross-file data, PRJ loading and app-specific runtime
publication remain separate future work. No scaffolding is added for them here.

Publication renders/validates the complete program first, then replaces individual
files and writes the manifest last. It removes the old manifest before mutation;
I/O failure can leave partial files without a manifest. There is no crash recovery,
writer locking or verification of edits to previously owned files. Operator cleanup
may be required after interrupted publication. A corrupt/unsupported manifest
refuses cleanup. Callers must check command success before building; an old bundle
preserved after semantic failure is not a successful new compilation.
