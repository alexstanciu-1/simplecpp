# Public runtime API generator

Doc Status: supporting

The production generator runs on **64-bit PHP 8.5 or later**, with no Composer
packages. It reads runtime metadata, publication requests and native C++ target
facts; prepares the requested API; then renders C++ headers, definitions,
`prepared.json` and `inventory.json`. It does not parse compiler source code.

The PHP implementation replaces the Rust API tooling. It preserves the public
behavior and generated bytes, without reproducing Rust's structs, enums or ownership
mechanics. Prepared records are PHP arrays. Object-valued JSON maps use `stdClass`
to preserve the distinction between empty objects and lists. The prepared description
is also the rendering input, avoiding a second serialization model.

## Owners

- `generate.php`: command dispatch, input reads, publication and freshness checks.
- `php/input.php`: small JSON reader and metadata validation helpers. JSON strings
  use PHP's decoder; container/number handling preserves decoded duplicate-key
  rejection, number spellings, object/list distinctions and a 128-container limit.
  Semantic integer fields require exact nonnegative PHP integers; no supported
  field requires values beyond the signed 64-bit host range.
- `php/target.php`: explicit C++ target facts/context validation.
- `php/scalars.php`: integer, boolean, null and floating API preparation.
- `php/families.php`: strings, vectors, carriers, hashes, datetime and record ownership.
- `php/boxed.php`: optional mixed/dynamic publication with measured inline layouts,
  explicit scalar factories and same-family container operations.
- `php/render*.php`: rendering from prepared facts; no promotion or source admission.
- `templates/*.cpp.tpl`: readable C++ fragments with named `@placeholder@` slots.
  These retain the existing output spelling; no Rust source is a build input.

Runtime semantics remain in `runtime/src/` and the family contracts in `specs/`.
Native layouts come from `tools/layout_probe/`, not PHP's host object layout.
External record traits remain C++ compilation obligations.

## Commands

From `v0.2/`, configure/build with Clang, libc++, Ninja, mold, PHP and Python:

```sh
cmake --preset default
cmake --build --preset default
ctest --preset default
```

CMake selects `PHP_EXECUTABLE` and creates two launchers in the build directory.
The positional runtime launcher supplies that build's explicit native facts:

```sh
./build/clang/scpp_api_generator runtime/metadata/runtime.json \
  runtime/metadata/publication.json build/clang/generated --check
```

The general launcher accepts the same commands as `php tools/api_generator/generate.php`:

```text
emit-runtime METADATA PUBLICATION FACTS CONTEXT OUTPUT [--check]
emit-scalars METADATA PUBLICATION FACTS CONTEXT OUTPUT [--check]
prepare-runtime METADATA PUBLICATION FACTS CONTEXT
prepare-scalars METADATA PUBLICATION FACTS CONTEXT
prepare-integer-construction METADATA PUBLICATION FACTS CONTEXT
validate-target FACTS CONTEXT
```

Preparation commands print JSON. Successful generation/check prints JSON containing
`status` and `artifacts`. Failures exit 1 with stderr and no success output.
Scalar projections reject non-scalar demands; complete runtime preparation validates
registered optional-family metadata even when that family is not requested.

Complete preparation/rendering precedes cleanup and writes. The output root is
dedicated generated storage. Normal generation fully clears `.hpp`, `.cpp` and
`.json` files recursively, then emits the complete new publication. Other extensions
are preserved; symlink directories are not followed. The versioned `inventory.json`
manifest (`generator`, `version`, `files`) is written last. Bump `OUTPUT_VERSION` in
`php/publication.php` when the output contract changes; old/malformed manifests need
no migration because regeneration always starts with cleanup.
`--check` is read-only and rejects missing, changed or obsolete generated files.
Publication is per-file, not transactional.
Do not run concurrent writers against one output directory.

## Rebuilds and proofs

Every CMake build checks native target context; unchanged probe files keep their
timestamps. Changes to PHP sources, C++ templates, metadata, publication or native
facts invalidate generation. An unchanged build does not regenerate or recompile.
`BUILD_TESTING=OFF` still runs the production probe and generator.

The frozen fixtures are independent regression references, never production inputs:
128 accepted runtime cases and 19 scalar cases require exact generated bytes;
249 runtime and 537 scalar cases require rejection. The scalar suite also compiles
the 2,692-signature matrix. CTest covers publication/freshness, native probe
invalidation, public header boundaries and compiled runtime consumers. PHP tests
cover lexical numbers, Unicode, duplicate keys, depth, target validation and
hash/datetime/layout contracts formerly covered by Rust unit tests.

```sh
cmake --preset ubsan
cmake --build --preset ubsan
ctest --preset ubsan
python3 -B tests/build_cutover.py
```

The source-only proof removes the compiler from a temporary export and verifies that no Rust source
or toolchain configuration is present, then builds/tests the runtime, checks PHP/template invalidation,
and exercises production builds with datetime enabled and disabled.

The compiler is now PHP: `compiler/my-try/` is being mined incrementally into
`v0.2/compiler/`. Rust sources and toolchain configuration have been removed.

## PHP replacement validation — 2026-10-29

- All 38 CTest checks passed in the fresh source-only Release export and in UBSan.
- Frozen artifact fixtures were unchanged; runtime and scalar parity/rejection gates
  passed, including the compiled 2,692-signature scalar matrix.
- The source-only export passed without compiler sources or Cargo configuration.
  Metadata, publication, PHP source, C++ template and target-flag edits each triggered
  regeneration. An unchanged build performed no generation or C++ compilation.
- Production core and datetime enable/disable builds and demos passed. Core symbols
  remained independent of datetime.
- One source-only observation: default publication generation took 0.167 seconds;
  unchanged build/probe checking took 0.407 seconds. These are local observations,
  not a cross-machine performance guarantee.

The [boxed publication contract](../../specs/boxed_slice.md) describes the optional
`boxed` request. Native facts measure the actual private boxed layout; the generated
public classes use opaque inline storage with compile-time ABI checks.

## Core and numeric demand

Core's default integer/byte types are int64 and distinct byte; float64 remains core.
Additional integer widths require `"modules": ["numeric"]` in publication metadata.
Only explicitly requested types/operators are emitted. The build option
`SCPP_ENABLE_NUMERIC=ON` composes `runtime/metadata/numeric_publication.json` with
core. This is API publication selection, not implemented source-level PRJ parsing.
See [the numeric/byte and cleanup contract](../../specs/numeric_module.md).
