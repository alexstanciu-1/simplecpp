# Bootstrap inventory of multitype parameters and returns

Doc Status: planning

Snapshot: `cc0a9bbd7`, 20 November 2026.

Unit of count: one declared parameter or return position. The PHP token scan covered functions, methods and closures in the v0.2 compiler, with generated PHP counted separately. It excluded examples, tests and tools, skipped comments, and counted the type before a parameter name or after a return colon. Reversed arms count as the same contract. Properties, PHPDoc element types, catch clauses and arithmetic operators fall outside this inventory. Calls are verified against parameter contracts rather than counted as additional signatures.

Explicit unions and intersections account for 39 handwritten parameters and 17 handwritten returns, plus 10 generated parameters and 21 generated returns. All explicit compound parameters counted here are required and passed by value. Separately, shorthand `?T` appears on 220 handwritten parameters and 94 returns, plus 57 generated parameters and 82 returns. Those counts establish where presence occurs; native support still depends on the payload and its ownership.

## Closure backlog in dependency order

Work one verified slice at a time. The census above remains the baseline snapshot. The first three slices establish what ordinary declaration interfaces and the existing compound ABI can express before considering a new representation.

1. **Duplicate diagnostic sites — implemented.** Both original parameters now take `ast_declaration_site`. Its three existing queries supply the name, its token position and the lexical source root. A catch binding and a conflicting local exercise different providers. The regression pins the full diagnostic including both coordinates in every flavor. Cross-unit addition, repeated rejection and deletion were compared with fresh compilation. [Diagnostic](../../compiler/03_parse/collect/diagnostics.php) · [Regression](../../compiler/tests/duplicates.php)
2. **Emitter declaration inputs — implemented.** Header publication and private prototype emission already know which declaration they are rendering. Both now call the same four typed C++ renderers for enums, records, functions and globals. In all three flavors a fixture using all four produced byte-identical headers and sources before and after the split, including after an enum edit and recovery from a deleted function. The header-dependency regression uses a bool-to-int signature edit to isolate a header-only change. [Emitter](../../compiler/05_backend/cpp/emit.php) · [Header publication](../../compiler/05_backend/cpp/headers.php) · [Rebuild proof](../../compiler/tests/unit_headers_native.py)
3. **Existing class and interface ABI — representative port shapes verified.** The [property and collection proof](../../compiler/tests/bootstrap_property_collection_native.py) routes both writable-property arms to concrete helpers and observes writes through the original owners. It forwards an empty indexed destination, tests the additional sequence capability for populated destinations, and calls the keyed capability through its interface. An explicit class-typed local projects the intersection to its existing base view before a further interface guard. The union uses the common object owner; each intersection carries its base owner and a non-owning interface pointer. Keep the owner live across the operation; shortening temporary retains is a native performance question. The [parser return proof](../../compiler/tests/union_pipeline_native.py) covers return forwarding across source units. These are signature/ABI proofs; the complete PHP property walk and collection-literal algorithms still belong to the actual port.
4. **Named-callable and runtime lookup boundaries — verified for bootstrap.** The [runtime lookup proof](../../compiler/tests/bootstrap_runtime_lookup_native.py) returns an existing fixed descriptor, an existing overload descriptor or an empty class owner across a source-unit boundary. An optional common base view is a viable native port shape. The PHP registry continues to express those outcomes directly. The same fixture exercises real generated bindings: a source declaration shadows `strlen` and deletion restores the runtime binding; a change to the key type selects a different boxed `has` overload. Bad selector types, wrong arities, missing callees and recovery are compared with fresh compilation. The callback binder rejects both missing and extra operands. [Signature inspection](../../compiler/tests/callable_signature_native.py) covers the read-only consumer; [named callback lowering](../../compiler/tests/named_callbacks_native.py) verifies direct target identity and exact signatures; [called-method retirement](../../compiler/tests/called_method_lifetime.php) verifies that removing the last caller releases its specialization and retains the sibling. The proof introduces no runtime lookup tag or per-query allocation. The native registry itself remains porting work.
5. **Five-way name-binding return — replaced by operation-specific queries.** [Prepared names](../../compiler/03_parse/structures/common.php) expose `local_binding()` for guard analysis, transfer eligibility, indexed storage and local-only emission. It follows a narrowing guard to its original local. Inspection and consumers requiring the actual object use `declaration(): name_binding`. The interface exposes the symbol key; local inspection still emits the storage ID. Static destinations, mutable-reference diagnostics, switch/match labels and value emission distinguish concrete targets when their behavior differs. Globals and named constants still resolve through the live symbol entry; enum cases, runtime constants and locals retain their existing links. Reset clears the original binding. The [native fixture](../../compiler/tests/bootstrap_name_binding_native.py) checks all five sources of values, edits, shadowing and fresh/incremental recovery. The [global test](../../compiler/tests/globals.php) checks the old occurrence across replacement and tombstoning. No occurrence tag or new stored reference is needed.
6. **Scalar facts and sentinel results — bounded contracts verified.** The [native proof](../../compiler/tests/scalar_result.cpp) uses a trivially copyable transient payload and a known bit. The prepared destination type determines the active scalar member; known null requires no payload read. The [PHP evaluator test](../../compiler/tests/constant_evaluation.php) checks signed zero, maximum int64 and an evaluator declining a known input. The [three-flavor fixture](../../compiler/tests/scalar_fact_edits.py) exercises generated int-to-bool conversions through initialization, assignment and read, with fresh/incremental recovery and preparation-only measurements. The retained AST and PHP evaluator need no layout change. [Return conversions](../../compiler/03_parse/structures/functions.php) retain a single numeric code. Entry preparation supplies the existing proven/checked integer codes; the enclosing function selects the process-exit or ordinary destination binding. The [nested-return proof](../../compiler/tests/entry_binding.php) uses the same checked code for both destinations and checks their distinct inspection names and generated calls. Keyword literal preparation now separates a boolean payload from a known literal identified by its type alone. The [literal tests](../../compiler/tests/literal_families.php) check both booleans, null and the two explicit carrier sentinels. The [input scanner](../../compiler/01_prepare_inputs/changes.php) normalizes an unresolved output path to absence before traversal. Only a resolved directory can match an exclusion. The [loading regression](../../compiler/tests/loading_plumbing.php) covers first capture, unresolved input and exclusion after publication. The inspection writer places numeric strings, JSON booleans or JSON null directly into the host report. Expression rows retain the independent known bit. The [CLI and panel regression](../../compiler/tests/inspection_scalars.py) covers scalar identity, exact numeric spelling and converted globals in a separate file. Full uint64 evaluation remains v0.3 debt.
7. **Audit shorthand nullable types by payload, then freeze coverage.** Check written `?T` against existing scalar carriers, optional owners, borrowed references, host values and capability interfaces. Some are optional PHP implementation handles. Inspect input defaults and reference modes separately for this group. For each contract record an executable native proof, a semantics-preserving port adaptation, or an explicitly approved deferral.

## Completion criterion

Run PHP/C++/JS source fixtures for every admitted language shape, with successful calls, rejection and fresh/incremental recovery. Include a cross-file caller and callee, return forwarding, and header/ABI updates after a declaration edit. Verify exact canonical override contracts for unions and distinct slot names when the native owner is shared. Exercise native lifetime where selected alternatives outlive the call. For generator-owned changes regenerate and compare signatures at every override. Bootstrap closure means every census row has a disposition and a proof for the actual consumer. General N-arm syntax, arbitrary heterogeneous unions, union references/defaults, variance, intersection returns, compound callback components and nested union/intersection syntax each require separate evidence and policy before becoming language goals.
