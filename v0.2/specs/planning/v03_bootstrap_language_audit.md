# Can v0.2 compile a close translation of its own PHP compiler?

Doc Status: planning

Audit date: 2026-11-13. Source baseline: `e3cbfe1b2`, including the bare-receiver and integer property-compound changes that landed during review. Target: the PHP flavor accepted by the active v0.2 compiler. The intended first native compiler is v0.3.

## Assessment

v0.2 can already express much of the code *inside* a compiler method. Examples include checking a token range, updating a bit mask, comparing strings, constructing a record, calling one of its methods, or updating an exact-type argument by reference. It can also share one concrete record allocation across aliases, test its identity, and hold weak links. Those are substantial parts of a bootstrap.

The main blockers appear where methods and data structures meet. A parser produces several kinds of expression through one base type. The analyzer asks which operations a type implements. A session stores collections of these same objects, passes the collections between stages, and retains some objects across edits. The backend consumes those settled facts. Translating the bodies of the methods alone would leave these central relationships unrepresentable.

## Scope and standard of evidence

A **clean** translation preserves the original decision, type relationship, ownership and failure behavior with comparable or simpler code. **Partial** means the supported case and the remaining limit both matter. **Gap** means an observed use would require duplicated decisions, extra mutable state, a weaker invariant, or a change to the architecture. **Local alternative** identifies a simpler spelling or representation for the particular use. These judgments describe features, so one source file can supply examples in several categories.

The inventory covered every production PHP file under [the active compiler](../../compiler/README.md). Counts by owner are 6 input, 2 tokenizer, 32 parser/collection/AST, 8 analysis, 8 backend, 1 native target, 11 compiler coordination, 9 type model, 6 host, 2 entry/bootstrap, and 12 generated files (97 total). Generated files include the local runtime publication ignored by Git. All three syntax adapters are implementation inputs because v0.3 must still understand all three flavors. Tests, examples, development tools, host PHP outside this compiler, and C++ text inside emitted strings are outside the source inventory. Library calls, container methods, OS facilities and runtime bindings are outside the gap count. The language rules that let a caller store, pass, inspect or iterate their values are in scope.

The source census used PHP 8.5 tokenization with parse validation, including ignored generated PHP. Distinctive constructs were inspected in context. For scale, there are 560 `instanceof` tokens across 42 files, 257 `foreach` across 40, 169 `match` across 26, 123 `??=` across 22, 32 arrow functions across 11, and two `yield` sites in a single method. Counts include generated definitions. They describe reach, not priority or percent completion. Reserved words that occur only inside the compiler's own keyword tables do not count as language uses.

Status below combines the [active frontend contract](../compiler_frontends.md), implementation and focused tests. The [inheritance](../../../specs/inheritance_v0_2.md) and [exception](../../../specs/exceptions_v0_2.md) specifications inform the intended meaning. A specification, a donor implementation or a native runtime type alone does not establish acceptance by this compiler.

## Checks performed

The PHP-flavor CLI was exercised with 42 isolated input programs and the checkout's Clang layout facts. Each program went through `php v0.2/compiler/main.php cpp php INPUT FACTS OUTPUT.cpp`. Success means preparation and C++ emission completed. A rejection applies to the tested form. These probes did not build or execute native binaries.

| Probe family | Observed result |
| --- | --- |
| Positive baseline | Emitted C++ for a concrete shared Point, alias mutation and same-handle identity, scalar for loop and by-reference call, local scalar vector/hash writes and reads, integer spaceship, outer-local branch assignment, scalar short circuit, string ordering and byte comparisons. Two further probes emitted C++ for bare `$this` as a value and bitwise/shift compounds on an instance field. Acceptance of a comparison does not imply its truth value. |
| Declarations and control flow | Rejected class/extends, interface, enum, readonly field, union parameter, foreach, match, ternary, coalescing, try/finally, arrow closure, value-producing postfix update, and call with trailing comma. A name introduced separately inside both branches remained unavailable after the branches. |
| Representation | Rejected hexadecimal source literal, int32 local with the default publication, vector of a user record, vector field, populated vector literal, and static shared-handle field (both omitted initializer and explicit null). |
| Collection boundaries | A hash-reference signature alone emitted C++. Calling it with an actual hash failed at argument binding. Vector value and reference calls, vector return, inferred copies of vector/hash locals, vector identity comparison and vector condition also failed. This is why feature status has to include the caller. |

Two examples of probe inputs, in the syntax accepted by the PHP-flavor CLI:

```text
struct Point { public int $x; public function getX(): int { return $this->x; } }
$p = new Point(); $q = $p; $q->x = 7;
if ($q === $p) { return $p->getX(); }
return 0;
```

```text
function fill(hash<int,string> &$values): void { $values["a"] = 1; }
$values hash<int,string> = [];
fill($values);
return $values["a"];
```

The first emitted C++. The second reported “Hash argument passing is deferred” at the call. Eight existing PHP suites also passed during the audit: typed functions, mutable reference parameters, string indexing, vector operations, hash operations, carrier values, dependency watches and incremental frontend. The last two validate behavior of the **PHP implementation** that a translation must preserve. Existing native tests linked above provide additional evidence for delivered slices. No full translated stage or v0.3 executable has been built as part of this review.

Fail a staging write and verify cleanup. These exercises distinguish language support that only recognizes syntax from support that preserves the compiler's behavior. |

These are proposed readiness checks. Progress can be recorded by moving individual rows to clean when an actual source-shaped caller and its failure/lifetime behavior pass together.
