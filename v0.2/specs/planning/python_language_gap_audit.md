# Python language gaps and shared compiler owners

Doc Status: planning

Audited v0.2/develop-php at `9309e7572` after paired hash traversal. This is a backlog for the typed Python source flavor. The comparison baseline is the Python 3.15 language reference. The audit covers language families and meaningful subcases, including behavior behind accepted syntax. It excludes library APIs, built-in function inventories, tooling and CPython interoperability. An entry describes the active v0.2 compiler. A feature of upstream PHP, ECMAScript or ISO C++ alone supplies no implementation evidence. [Python reference](https://docs.python.org/3.15/reference/index.html) · [Grammar](https://docs.python.org/3.15/reference/grammar.html) · [Flavor contract](../compiler_frontends.md#python-syntax-flavor-in-v02)

## How to read the decisions

**Implement** means the bounded spelling has a peer equivalent, an existing syntax and semantic owner, and a local frontend route. **Discuss** means a peer offers only a partial equivalent or the behavior, ownership, invalidation or scope needs a decision. **No peer** means discuss before scheduling; no implemented equivalent for the stated behavior was identified. **Contract** means a deliberate difference already affects ordinary code. Changing it requires a language decision. These are engineering assessments from inspection, independent of priority. A parser accepting a token, a possible source rewrite or a native C++ feature does not establish end-to-end coverage.

## Verified starting point

Typed functions and positional calls, initialized typed locals, arithmetic including true division and integer floor division/modulo, scalar comparisons, bool-only logic, conditional expressions, indented branches and loops, simple exits, typed vector/hash operations, key-only and paired hash traversal, single-base classes, field/method access, marked virtual dispatch, typed handlers, rethrow and finally have Python coverage. Peer-flavor projects can call across the boundary. Ordinary signed expressions already parse. Hex and octal literals already reach preparation. These need no new Python syntax slice. [Existing verification and limitations](python_flavor.md) · [Frontend suite](../../compiler/tests/python_frontend.php) · [Mixed native suite](../../compiler/tests/python_flavor_native.py)

Focused checks using Source_Frontend::prepare during this audit accepted `-x`, `0x10`, `0o10`, a conditional expression and a positional call. They rejected `~x`, `x & 1`, `x << 1`, `x ** 2`, `x is None`, `x in h`, `0b101`, `1_000` and a trailing call comma. Each probe had declared, typed operands. All other classifications below are source and contract inspection.

### Completed since the inventory

Python `super().method(args)` now uses the existing lexical-parent call node in statements and expressions. Preparation resolves the method on the lexical base and dispatches on the current object. Explicit base construction still requires an initial `super().__init__(...)`. A different first method call follows implicit base initialization. The frontend regression checks authored spans, the receiver-free AST, invalid contexts and the empty argument list on `super()`.

The Clang inheritance matrix exercised cpp/php/js base providers. With the Python caller untouched, editing the ordinary and virtual base method bodies changed the output and return value. Removing the ordinary method produced the fresh-build diagnostic and preserved the last good bundle and manifest. Restoration and provider deletion/recovery matched the previous artifacts, and the final fresh-equivalent bundle ran successfully. The existing dependency path re-emitted the provider, API, child and entry on the body edit and reused unrelated work. The native reuse regression distinguishes frontend emission from recompilation. It compares all generated C++ and header bytes and timestamps across the base body edit, then uses a persistent Clang/Ninja build to check exactly which object changed. Across cpp/php/js providers, only the base translation unit changed on disk and recompiled.

The rebinding regression keeps the Python child and entry untouched. The child calls `super().score(self.value)` with a field set during construction. Removing the base override selects the grandparent implementation, which adds 20 to the argument. Restoring the override selects the base again. Each transition checks the qualified target in the child's C++, compares the resident bundle with a fresh build and runs the incremental executable. All three providers produced exit statuses 10, 30 and 10 for base, grandparent and restored base dispatch. [Mixed regression](../../compiler/tests/python_flavor_native.py) · [Native rebuild check](../../compiler/tests/inline_adapters_native.py)

Python now admits integer complement, binary AND/XOR/OR and the three corresponding compound updates on plain local storage. Python grammar owns grouping. From tightest to loosest the relevant levels are unary complement, arithmetic, bitwise AND, XOR, OR, comparisons, boolean not, and, or. The parser produces the peer AST nodes. Preparation uses existing operand types and the published scalar operators for promotion and checked write-back. Shifts, power and annotation unions remain separate decisions.

The mixed Clang regression uses cpp/php/js providers. It checks signed and byte complement, precedence, an RHS call that mutates its destination, and byte write-back. Changing the peer mask from 8 to 256 reuses the Python caller and triggers a native range failure. Changing the mask provider's result type to float rejects the unchanged caller and preserves the prior publication. Restoring the integer provider recovers fresh-equivalent artifacts and execution. [Frontend regression](../../compiler/tests/python_frontend.php) · [Mixed native regression](../../compiler/tests/python_flavor_native.py)

With a uint8 destination initially holding 255, each peer supplies the integer mask 256 once. AND computes zero and stores it. XOR computes 511 and reports integer_cast_out_of_range on write-back. Together these cases distinguish checking the result from prematurely narrowing the mask.

The compatible signature regression changes the same peer function from int to uint8 and back to int while the Python caller stays untouched. At the specific `small |= mask()` assignment, the checked int64-to-uint8 conversion disappears for the byte result and returns for the integer result. Each edit re-emits the peer and caller, reuses the idle unit, matches a fresh C++ bundle and runs with identical native behavior.

Python `x is None` and `x is not None` now parse at comparison precedence into the existing strict comparison AST. The literal `None` maps to the shared null value. Nullable carriers that accept an empty state use their published presence binding; shared class, interface and struct handles test their owner. Zero, a successful false value, an empty string and a live object all count as present. Null-typed calls retain their effects. Result and sentinel carriers reject during preparation, including when their payload would be successful. The boolean test establishes no narrowing fact.

The Clang regression tests nullable scalars and backed enums, required and optional class/interface handles, explicit shared struct owners and an effectful null-valued function across cpp/php/js providers. Output records each operand call once. A provider body edit switches from absence to a present zero and reuses the Python caller. Changing only its return type from nullable to result rejects at the unchanged caller, matches the fresh diagnostic and preserves the last good manifest and C++ bundle. Restoring the nullable signature recovers fresh-equivalent artifacts and native behavior. [Mixed native regression](../../compiler/tests/python_flavor_native.py)

With the same Python caller, the cpp, php and js providers each changed from a present zero in nullable<int> to an empty ?Node and back. The native exit status followed 9, 8, 9, with one probe call per run. Each signature edit re-emitted only the provider and caller, reused the unrelated units and produced the same generated C++ and headers as a fresh build. Removing the provider file produced the same unknown-function diagnostic as a fresh build and preserved the last good manifest and artifacts. Restoring it re-emitted only the provider and caller, reproduced the previous and fresh artifacts, and ran with the original output and exit status.

Python typed-hash membership uses the shared binary AST and the mapping's published key-presence signature. Both spellings require the exact key type and evaluate key before mapping. Generated C++ calls the published member directly for a local receiver and captures the key when a mapping expression could change it. Source functions named hash_contains do not affect the operator. No traversal, value lookup or additional preparation pass is involved.

The cpp/php/js Clang matrix covers present zero and empty-string values, missing keys, application-valued hashes, observable operand order and a mapping call that changes the key local. A failing key skips the mapping. A provider body edit reuses the caller; changing the key type or removing the provider gives the fresh-build diagnostic and retains the last good publication. Restoration recovers fresh-equivalent C++ and native behavior. [Mixed native regression](../../compiler/tests/python_flavor_native.py)

The Python entry emits one presence call per membership expression (seven sites), with no value read or traversal. A separate unchanged caller follows int-key to string-key to int-key hash signatures in the same resident session for each peer flavor. Only the provider and caller re-emit. The three stages match fresh C++ artifacts and produce hit, miss and hit with one key call before one mapping call.

## Expression and collection gaps

| Python feature | Closest implemented peer | Decision and reason |
| --- | --- | --- |
| General `a is b` | Shared object allocation identity | **Implemented** for standalone shared-handle `is` and `is not`. An alias retains allocation identity through an interface view. Two empty handles compare identical across declared types. Scalar and copied collection identity have no general equivalent. |
| Membership in sequences, strings, sets, arbitrary objects | Vector traversal and byte strings supply partial building blocks | **Discuss** equality and substring semantics for typed sequences. **No peer** for user-defined containment/iteration fallback. |
| Comparison chains | Shared typed comparisons | **Implemented** for adjacent pairs admitted by `== != < <= > >=` and typed-hash `in` / `not in`. Each operand executes once in source order until a comparison fails. Each pair is prepared even on a skipped path. Chains involving identity remain deferred. |
| Truth testing, operand-valued and/or | Shared conditional truth tests and lazy bool expressions | **Contract.** Python logical operands currently require bool. Operand-valued branches need result types, lifetimes and short-circuiting. |
| Shifts and shift updates | Checked fixed-width shift helpers | **Discuss.** Large counts, negatives and signed width differ. Decide bounded semantics and verify Python shift precedence alongside angle-bracket types. |
| Power and power update | Shared power operator/helper | **Discuss.** A negative integer exponent can change result type in Python. Power binds differently on either side of unary minus. |
| Float floor division and modulo; numeric division updates | Existing Python binary division strategies and shared compound machinery | **Discuss.** Float rounding, infinities, signed zero and failure need a contract. For `/=`, `//=`, `%=`, select the Python operation and decide checked write-back to a declared destination. |
| String/sequence addition, repetition, formatting with %, collection comparison | PHP concatenation, runtime string operations, scalar comparison capabilities | **Discuss.** Decide admitted operand pairs, equality/ordering, element copies and encoding. **No peer** for general Python formatting or reflected operator dispatch. |
| Matrix multiplication and augmented form | No published matrix operation identified | **No peer.** Needs an actual operand capability and a result contract. |
| Unbounded integers, complex literals/arithmetic, bool-as-int, unrestricted mixed numeric equality | Shared bounded scalars and conversions | **Contract** for bounded scalars and strict bool. **No peer** for arbitrary precision or a complex scalar family in this path. |
| Negative indexes, slices, extended slices and slice assignment/deletion | Checked indexes, vector set and byte string helpers | **Discuss.** Specify index normalization, step, copy/view, failure and mutation. String indexing also raises a byte versus Unicode code-point decision. |
| Uncontextualized list/dict displays, mixed element types, application-valued populated hash literals | Typed local initialization and application hash writes | **Discuss.** Preparation currently gets a destination contract. Determine inference, ownership and publishing for each new expression context. |
| Tuples, set displays, starred displays, dictionary unpacking and merge | Fixed records, vectors and hashes are partial relatives | **No peer** for Python tuple/set values and arbitrary iterable/mapping expansion as a language facility. Decide representations and duplicate handling. |
| List/set/dict comprehensions and generator expressions | Loops and typed collection construction; synchronous cursor for lazy output | **Discuss.** Needs expression-local bindings, nested filters, and eager versus lazy lifetime. |
| Mapping views, pair iteration beyond contextual items, general iteration | Shared foreach capabilities, keyed advance, concrete iterator | **Discuss.** Standalone views require lifetime/mutation rules. A bounded typed cursor loop may reuse foreach after checking Python's current vector/hash admission and the binding mode. General iterator protocol has **no peer**. |

## Statements, binding and control flow

| Python feature | Closest implemented peer | Decision and reason |
| --- | --- | --- |
| First-write inference, annotation without initializer, function-wide binding | PHP declare-or-assign; cpp/js inferred declarations | **Discuss first.** Inference itself is cheap. Choosing block scope or Python function scope changes shadowing, branch joins, unbound reads and incremental dependencies. Annotation without a value needs definite-initialization rules. |
| Chained assignment, parallel assignment, swap, nested and starred targets | Single assignments and paired foreach slots | **Discuss.** RHS once, unpack failure, shared identity and target write order are observable. The loop key/value slots do not model arbitrary targets. |
| Walrus expression | Peer assignment in a condition | **Discuss.** Existing condition assignment is bounded. Python also permits named expressions in value contexts and comprehensions. Choose a bounded context and binding rule. |
| Augmented updates on attributes and subscripts | Peer indexed compounds and field writes | **Discuss.** Receiver/key evaluation once, old-value capture, mutating RHS and write-back differ by target. Python plain field statements currently request simple assignment. |
| Arbitrary expression statements and docstrings | Discarded calls are supported | **Discuss.** Decide discardable expressions and diagnostics. Runtime docstrings/metadata have **no peer**. |
| Single-line suites and semicolon-separated simple statements | Peer statement lists and scoped blocks | **Discuss.** Feasible without new AST, but terminator handling, suite boundaries, diagnostics and source spans change together. |
| Loop else and try else | Shared loops, break, handlers and finally | **Discuss.** Loop else requires normal exhaustion; try else runs outside that try's handlers and before finally. No equivalent clause identified. |
| Structural match/case, guards, captures, OR and nested patterns | Peer switch and expression match on published dispatch types | **Discuss.** Literal-only dispatch is a possible first slice. Existing case labels do not bind captures, destructure objects or implement guarded patterns. |
| assert with optional message | Conditions and throw | **No peer** for assertion semantics including lazy message and disabling policy. |
| del targets; global and nonlocal declarations | Peer collection mutation, globals and scopes | **Discuss.** Deleting a binding, field or entry are distinct operations. Global declarations need module identity. Enclosing writable cells for nonlocal have **no established Python equivalent** here. |
| with / multiple context managers | Shared finally and runtime ownership | **No peer** for enter/exit protocol, partial acquisition, exception arguments and suppression. |
| except without binding, tuple of exception classes, bare except | Shared typed handlers with mandatory binding and multiple clauses | **Discuss.** Current catch AST has a produced binding. Decide unnamed handlers and caught universe. Inspect whether alternatives share a body without duplicating scopes. |
| Exception cause/context, raise from, exception groups/except*, arbitrary finally exits | Typed exception transport, rethrow and bounded finally flow | **Discuss** finally exit differences. **No peer** for cause chains or subgroup splitting/reassembly. |
| yield statement and iteration over its result | All three peers implement typed synchronous yield and concrete cursors | **Discuss** the complete producer/consumer slice. Producer syntax can reuse ast_yield_statement with a newline terminator. Python foreach currently excludes that cursor. Decide return annotation and resumed iteration first. |
| yield as an expression, yield from, send/throw/close protocol | Bounded synchronous producer | **No peer** for the full bidirectional/delegating protocol. |
| async def, await, async for/with, async generators | Synchronous suspension only as a partial analogy | **No peer** for Python coroutine/awaitable contracts in the active path. Keywords alone confer no coverage. |

## Functions, classes, modules and types

| Python feature | Closest implemented peer | Decision and reason |
| --- | --- | --- |
| Keyword calls, positional-only and keyword-only parameters | Shared positional calls, named declarations and literal defaults | **Discuss first.** Keyword binding would make parameter names a public caller dependency. Evaluate arguments in authored order even when parameter order differs if Python ordering is promised. Test a parameter rename in a resident session. |
| Variadics, starred calls and double-star keywords | Typed parameter list and collection passing | **No peer** for Python argument expansion, duplicate keyword rejection and rest binding as one protocol. |
| Definition-time defaults including mutable objects | Shared prepared defaults | **Discuss.** Python evaluates defaults when the definition executes and retains their identity across calls. A default expression inserted at each call cannot reproduce that. |
| Untyped signatures, first-class functions, nested def, lambda, closures and recursion through captured names | Peer named callbacks and capture-free typed lambdas | **Discuss.** A contextual capture-free lambda is a smaller candidate. Python lambda supplies no parameter/result types; full closures require capture, cell lifetime and binding rules. |
| Static methods and class-qualified calls | Peer static methods and JS dotted call syntax | **Discuss.** A compile-time staticmethod marker is plausible. The Python parser currently requires self on methods. Verify both class and instance access and decide decorator/name shadowing before scheduling. |
| Class methods, properties, general function/class decorators | Limited virtual/override markers and static members | **Discuss** a bounded class receiver or property. **No peer** for general executable decorator stacking, rebinding and descriptors. |
| Multiple bases, Python method resolution order, cooperative super, class keywords | One base, multiple explicit interface capabilities, fixed ancestor dispatch | **Discuss.** Interfaces do not supply Python multiple-base state or method resolution. General super proxies and dynamic base selection have **no peer**. |
| Dynamic attributes, class body execution, class versus instance state, special methods, metaclasses | Fixed fields, constructors, static storage, virtual methods | **Contract** for fixed records. **No peer** for dictionaries of attributes, arbitrary executable class namespaces, metaclass construction or general Python protocol dispatch. |
| Type aliases, parameterized functions/classes, type parameter bounds/defaults, general unions, annotation expressions and runtime annotations | Shared canonical types, generic type references and bounded signature forms | **Discuss.** Python type expressions and type-parameter scopes are different from selecting an existing typed runtime specialization. Runtime annotation evaluation/introspection has **no peer**. Include common Python spellings such as list[int], dict[K,V], T or None written as a union, and a None return annotation as separate surface decisions. |
| import/from/as for project symbols | Peer source import aliases, namespaces, module publication and watches | **Discuss first.** A static project-only mapping is plausible. Decide the meaning of a dotted module, imported name, aliases, collisions and cycles. Verify deletion and restoration of the imported declaration. |
| Relative/star/lazy imports, package loading, executing module top level once, module objects, future directives | Shared compile-time module manifests only | **No peer** for Python import execution and module identity. Also distinguish script entry return in this flavor from Python module execution. |

## Lexical and literal gaps

| Python feature | Closest implemented peer | Decision and reason |
| --- | --- | --- |
| Binary literals and digit separators | Shared bounded integer literal parser supports hex/octal | **Discuss.** 0b and underscores were rejected in probes. Both scanner and literal decoding/validation must agree on base, legal separator positions, range and diagnostic offsets. Also check leading zeros against Python. |
| Trailing comma in calls and formal parameters | All flavors use the same positional list parser, which explicitly rejects it | **No peer** for these two lists. **Small decision.** Python-only relaxation could reuse the lists and preserve the close-parenthesis span. Do not generalize from a one-element tuple or a collection display. |
| Multiline/triple-quoted strings, raw prefixes, escape repertoire, adjacent literal concatenation | Shared quoted literals and byte decoder | **Discuss.** Original byte spans, embedded newlines, escape handling and layout must agree. A raw prefix changes decoding. Adjacent tokens must form one value. |
| f-strings including nested expressions, conversion flags and format specs; template strings | C++ interpolation and JS template interpolation | **Discuss** a narrow interpolated-string form using shared parts. Python formatting, conversions, debug expressions and template-string result objects have **no full peer**. |
| Bytes literals, Unicode strings and identifiers, normalization and source coding declarations | UTF-8 source scanner, ASCII identifiers and byte strings | **Discuss.** A bytes prefix needs a destination type. Unicode identifiers affect symbol identity and collisions; Unicode text affects length, indexing and ordering. Recognizing the source encoding separately affects byte diagnostics. |
| Tabs, formfeed, explicit line joining, physical line endings and BOM | Shared source positions and Python layout pass | **Discuss.** Spaces and implicit delimiter continuation already work. Python tab expansion, mixed indentation diagnostics and backslash-newline handling need lexer/layout proofs. |
| Soft keywords and context-sensitive names | Per-flavor word classification | **Discuss.** Recognize match/case/type in context and preserve legal ordinary names. Current flavor reserves self and super specially; standard Python allows ordinary bindings. |
| Ellipsis and other singleton literals, imaginary suffix, string template prefixes | Peer null/bool literals and fixed numeric types | **No peer** for those value identities in Python source. Recognizing punctuation or a suffix alone does not supply the value. |

## Existing syntax with observable differences

These are compatibility decisions even if no token is missing. Keep them visible when prioritizing the backlog.

| Example | Current flavor contract | Effect on future work |
| --- | --- | --- |
| Two effectful operands or arguments | Shared eager expressions can permit either evaluation order. Python specifies left-to-right expression evaluation and RHS before assignment targets. | Audit each new desugaring for effects, failure, single evaluation and retained lifetime. A native compiler probe cannot establish source semantics. |
| Assign or pass a list/dict, then mutate it | Typed value collections copy; shared object elements retain identity. | Python aliasing differs. Membership, augmented assignment and view lifetime cannot silently assume Python object identity. |
| Duplicate dict keys, iterate a hash, use a freshly bound key after a loop | Typed literals reject duplicates, typed hashes traverse in insertion order and fresh loop names are scoped. | Traversal order agrees for unmodified mappings. Duplicate-key handling and binding lifetime still differ. Preserve the published contract until explicitly changed. |
| Omit a type, mix branch result types, overflow a scalar or index below zero | Typed boundaries, bounded scalars, checked accesses and prepared conversions | A spelling may work on a subset of values. Test the rejection boundary and the successful values separately. |
| Inherit/replace a method or mutate class state | Typed record layout, explicit override on virtual replacement, shared class handles | Python late lookup and arbitrary method replacement would change dispatch, invalidation and ABI assumptions. |

## How to retire an item

1. Specify the bounded Python forms, an accepted example, a rejected neighbor, the exact peer implementation and any deliberate semantic difference. Prioritize common source patterns over grammar-production counts.
2. For an Implement item, show the shared AST and spans, identify the existing capability or binding, and use the existing preparation traversal. A new public symbol dependency, binding lifetime or prepared fact reopens the design decision.
3. Run native Python with cpp/php/js providers as applicable. Check results, effects and failures. Use small Python differential examples only where equivalence is promised.
4. Check body-only reuse, an affecting signature/capability change, failure and recovery against fresh output. For lexical-only changes, test offsets, stable unaffected units and unchanged peer tokens. Measure preparation cost if the work adds a traversal or retained state.
5. Promote to covered only after the frontend contract and tests agree. Discuss the remaining rows one at a time. Keep deliberate language differences separate from missing implementation.

### Comparison chain verification

The Clang regression runs one unchanged Python caller against cpp, php and js providers. The call trace covers a successful chain and a skipped call after either a false first or a false interior comparison. A body-only edit to the middle callee changes the trace while re-emitting only the provider. The frontend checks that grouped endpoints retain their full source span. A reference-mutating callee checks that the middle value survives a later write. Changing the skipped provider's result to an incompatible type or deleting it produces the same diagnostic as a fresh build. Restoring it checks caller invalidation, unrelated reuse, emitted artifact parity and native behavior.
