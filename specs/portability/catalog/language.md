# Strict language feature inventory and PHP authoring proposals
Doc Status: planning

Snapshot: 2026-09-21, v0.2 development. This is a catalog of feature families,
not a promise that every PHP form or every native runtime member is accepted.
Target status and converter status are separate. `proposed` means not implemented
in our portability tool. Existing normative specs retain authority. Examples in
proposal rows describe intent; annotation/helper grammar is not yet approved.

The converter remains local and type-blind. It can rewrite a declaration carrying
metadata, but cannot discover that an assignment elsewhere copies a value struct.
Such operations need explicit authoring intent, not cross-file analysis.
