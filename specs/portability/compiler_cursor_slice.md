# Expression cursor and typed-list portability slice
Doc Status: supporting

`compiler/src/03_parse/data/structures.php` is now ready. It retains the original
expression context enum and cursor constructor, fields and defaults. Only managed
imports and two adjacent vector annotations were added to those declarations.
Removing the annotations restores the adopted declaration bytes. Seven production
files are now in the explicit ready set, including all three parser data files.
The parser execution/handlers and tree storage are still outside that set.

## Explicit list intent

The PHP spelling is `public array $operands /** vector<int> */ = [];`, with
`vector<syntax_kind>` for operators. PHP runs normal arrays, used strictly as dense
lists. PHP++ receives an explicitly typed vector property. Local declarations can
use the same adjacent `vector<T>` annotation; documentary `@var list<T>` comments
are retained but are not a second source of conversion rules.

The annotation parser accepts one scalar/named element type, with lexical validation
and no name lookup. Nested generic containers, mixed/dynamic elements, keyed maps,
sparse arrays, array promotion and arbitrary PHP array behavior are not established
by this slice. Array properties require an explicit annotation and empty default.
Brackets preserve local indexing/append/literal syntax; PHP and native checking
own element/index validity. The shared proof uses integer and enum element types.

The central map adds ordinary PHP `count`, emitted as native `count`; one argument
and the dense typed-list contract are covered. No compatibility count override or
per-file function choice was introduced. Existing private policy tests still prove
that a future central override can shadow a PHP builtin consistently.

## Construction and mutation

The existing promotion owner now also handles mutable public promoted parameters
and named constant defaults. The cursor's context defaults to its explicit enum
case, node ID to zero, and mutable last-child ID to zero. Class assignment shares
the cursor, while assigning its integer list to a separate local yields an
independent mutable list in both executions. This distinction is tested directly.
Readonly properties retain the previously documented PHP-enforced/native-advisory
contract; no new enforcement claim is made.

For cross-file vector property reset, construct an explicitly typed empty local
and then assign it. Native v0.1.76 lowers a bare `[]` RHS on this property to mixed
instead of a vector; `cursor-01` retains that failure. The portable spelling used
in the witness is:

```php
$empty_operands /** vector<int> */ = [];
$cursor->operands = $empty_operands;
```

This uses locally written type intent and requires no property-type resolution in
the converter.

## Proof

[cursor-02](../planning/compiler_migration/results/cursor-02/summary.json) passed
PHP/native strict v0.1.76 execution and all fifteen compiler fixtures. The shared
witness covers default and explicit construction, mutable promoted fields, empty
counts, ordered append/index access, enum elements, shared cursor identity,
independent integer-list copying and replacement using a typed local. Converter
and prologue regressions passed. Final lexical-validation changes were checked to
produce exactly the same generated bytes as the native-tested output.

Stack pop, loops, parser expression execution, object-element list copying,
out-of-range behavior and nested containers remain subsequent portability work.
