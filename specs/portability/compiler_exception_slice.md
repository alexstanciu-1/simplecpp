## Framework ownership and assembly

`tools/php_portability/src/exception_policy.php` owns a fixed root-type spelling map
and the generated native exception hierarchy. PHP execution continues to use real
PHP built-in exceptions. The native implementation uses reserved global
`scpp_portability_*` names because v0.1.76 misresolves the runtime Exception base
inside a PHP++ namespace. These are implementation names, not authored namespaces.

After directory conversion, run:

```bash
php tools/php_portability/install_native_runtime.php GENERATED_DIRECTORY
```

This separate assembly command installs `scpp_framework/exceptions.phs`, owned by
`.scpp-native-runtime.json`. It does not change the converter's one-to-one source
manifest. It preserves unchanged timestamps and refuses symlinks, source-path
collisions, malformed state, unowned files and edits to owned framework output.
Run it after framework changes as well as first assembly. The native project then
composes that ordinary PHS file using its existing build workflow. The installer
uses individual atomic file replacements and assumes one writer; it is not a
whole-directory transactional publisher. A failure between source and manifest
publication can require restoring the previous owned state before retrying.

## Local type and control-flow policy

Supported explicit root names are `\Exception`, `\LogicException`,
`\InvalidArgumentException`, `\RuntimeException`, `\OutOfBoundsException`,
`\RangeException` and `\JsonException`. `\Throwable` is a catch/base spelling for
this supported exception family, not a promise about every PHP engine error.
The hierarchy is checked against PHP's actual parent classes. Constructors preserve
message, integer code and optional previous framework exception. Ordinary named
method calls are now admitted; native/PHP checking owns method existence and types.

Root qualification is required. The policy does not resolve aliases or infer user
class ancestry. General exception subclasses, inherited constructors, union catches
and finally remain unsupported by this converter slice. `Throwable` construction
is rejected. Reserved temporary and native-class prefixes cannot be authored.

The target emits multiple PHP catch clauses as repeated catches of the same C++
wrapper, making later clauses unreachable. The converter therefore parses a whole
try/catch chain as one AST node. It emits one framework-base catch and ordered
category checks whose ancestry masks come from the same fixed type policy. An
unmatched object is rethrown; a handler executes outside its protected try, so a
new exception from that handler cannot enter a later sibling catch. No symbol
lookup or source-language type inference is involved.

Catch variables are native framework-base handles within their selected branch.
The common exception API is covered; subtype-specific typed boundaries beyond it
are not established. Cross-static-type `===` identity also differs in the selected
target. Use the central `scpp\same_exception` operation when comparing exception
identity across base/derived handles; PHP uses actual object identity and native
code compares both handles through the framework base. The original exception
object is retained across cause links and rethrows.

## Proven scope and remaining debt

[exception-03](../planning/compiler_migration/results/exception-03/summary.json)
passes the shared PHP/native v0.1.76 witness, strict STAN and all sixteen existing
compiler fixtures. It covers actual backend configuration validation, success,
message/code, cause identity, defaults, ordered catches, unmatched propagation,
rethrow identity and handler exceptions escaping sibling catches. Earlier runs
retain the catch-order and cross-type identity failures that motivated the rules.
The generated framework source and its ownership manifest are saved with evidence.
Final diagnostic refinements produced exactly the native-tested generated bytes.

Run `python3 tests/portability/native_runtime.py` for assembly ownership/no-op
checks and PHP hierarchy verification. Converter and prologue regressions also pass.

This is a **handled-exception** contract. Native uncaught diagnostics still use the
underlying target's generic message path. PHP traces, engine Errors, arbitrary
runtime-originated failures, user exception subclasses and native JSON failure
translation are not implemented. Mapping JsonException's type does not implement
JSON operations. These limitations remain explicit debt before broader compiler
entry/error paths can be marked ready. Native readonly enforcement remains advisory,
as already recorded by the role-view slice.
