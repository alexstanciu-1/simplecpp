# Completing direct-call async/await in v0.2

Doc Status: planning

This milestone covers cooperative async free functions consumed directly by await or async_wait in the PHP, C++ and JS flavors. Its starting point is commit `c61e6ad8d`. The original estimate was 12 reviewable runs, with a range of 9–15. The runs group work by evaluation and lifetime requirements across all flavors and types.

The [async contract](../async_await.md) owns language semantics. The [implementation inventory](async_publication.md) describes the current boundaries. Async methods as producers, callable adaptation, first-class task values, cancellation, cross-thread execution, asynchronous iteration and a returnable fixed_array representation are separate milestones.

## Adopted decisions

- **Reference arguments (run 5).** Apply the existing binder to an ordinary call such as `update(slot, await child())`. A reference to an admitted named local denotes the same storage when the child completes. Broader borrowing from fields or collection elements needs its own lifetime contract. See [writable parameter rules](../../compiler/docs/collection_references.md).
- **Task payload transfer (runs 6–7).** Allow source evaluation and construction to fail through the existing producer exception path. Construct promise storage on successful return, retain nonthrowing native transfer and destruction, and remove the eager default-construction and move-assignment requirements where those operations disappear. Supporting a throwing move during delivery to the caller would require a separate failure and cleanup contract.
- **Handler and finalizer semantics (runs 8–10).** The ordinary [exception contract](../exceptions_v0_2.md) already defines replacement, rethrow, pending returns and cleanup order. Suspension should preserve those rules. Reopen discussion only if an async scenario exposes a genuinely unspecified observable behavior.

## Progress

**Run 1 complete.** Removed the async statement whitelist. The ordinary statement preparer and emitter handle a switch with a synchronous selector, case fallthrough and ordinary writes between suspensions. The native async fixture covers append, indexed assignment, indexed compound and increment, and field compound and increment. The selector runs once per dispatch. A case local survives the child await and is destroyed before fallthrough; break exits the switch inside a loop. Both incremental and fresh programs produce the same trace in PHP, C++ and JS. Deleting the child fails preparation, and restoring its edited body rebuilds one native object per flavor.

Boundaries identified in run 1:

- Suspension during operand evaluation still goes through the await-context and staged-result checks. Writes during suspension belong to run 2; selectors and other expression sites needing prerequisite statements belong to run 4.
- Catch and finally have their own exception-region restrictions (runs 8–10). Rejected foreach receiver lifetimes and nested yield cursors retain their separate ownership boundary.
- Yield requires a generator result. Base initialization is only parsed for derived constructors. Neither requires a duplicate async statement whitelist.

Baseline at `c61e6ad8d`: rebuilt the Clang async runtime and frame-boundary fixtures. CTest passed `async_runtime`, `async_frame_boundary` and `async_header_isolation` (3/3). The frame fixture verifies nested blocking waits on both success and failure and observes both guard destructions. The task recipe routes blocking extraction through the same `await_resume()` used by suspension; it checks the saved exception before extracting the payload. Run 6 needs to prove construction and destruction of the payload itself, including a never-started task, in addition to retaining these baseline checks.

**Run 2 complete.** A storage write can suspend while selecting an indexed destination or evaluating its key or RHS. The ordinary binder still owns writability and conversions. Field writes retain the selected owner. Indexed compounds save the key and converted old value before the RHS, then check the element again before replacing it. Plain stores keep key normalization and fixed-array bounds checks at the points required by the receiver contract. Lazy coalescing assignment belongs to run 4.

The retained-session fixture exercises a staged RHS that replaces a vector, a child that replaces a shared field owner, and a throwing child. Removing the original element produces a bounds error on write-back. An invalid boxed key and an invalid fixed-array subscript both suppress the RHS trace. Incremental and independent fresh native builds agree across PHP, C++ and JS. Deleting the child fails preparation in both sessions. Restoring the edited child rebuilds one native object per flavor. All 13 affected ordinary fixed-array, indexed-update and compound tests passed.

**Run 3 complete.** Nontrivial initializers, nested operands and selected ternary arms can now construct their results across suspension. The native fixture joins heap-backed strings and initializes an inline record with a required constructor argument and an observable destructor. Nested selections construct the local directly. A failed child skips construction and destruction. In an ordered call, a nested result constructs the argument snapshot and releases its input owner before the next child starts.

Incremental and fresh native programs agree in PHP, C++ and JS. Removing the record factory fails preparation and restoring its edited body rebuilds one native object per flavor. Earlier scoped-owner, unwind and ternary native traces also pass. This run covers expression storage. Task-promise payload construction remains scheduled for run 6.

**Run 4 complete.** Coalescing, coalescing assignment, switch and match now evaluate an awaited selector or fallback in the enclosing coroutine. The fixture checks present zero, missing values, successive match conditions, skipped throwing arms, and a selected throw with suspending arguments. It also exercises constructor and timer arguments, a subscript with an awaited receiver and key, and synchronous traversal of an awaited vector.

Positional and keyed literals finish each operand and conversion in order. Bulk inputs keep the published inline limit, use aligned heap storage above it and count fully constructed entries for exception cleanup. The native tests include a 513-element vector, nested inline byte arrays, and a hash of records with required constructor arguments. A child throwing while evaluating the second key destroys the first completed entry once. Incremental and fresh builds agree in all three flavors. Deleting the fallback child fails preparation, and restoring the edited source rebuilds one native object per flavor.

The await-context walk no longer maintains a separate expression whitelist. Ordinary grammar and binding still govern constant labels, writable places, initializer admission and receiver lifetimes. Capture-free lambdas have no async callable representation. Suspending arguments to methods, runtime calls and reference parameters belong to run 5. Typed catch and finally remain runs 8–10. Direct producer consumption, synchronous iteration and the existing exclusion of nested generator cursors remain milestone boundaries.

**Run 5 complete.** Ordinary source and runtime calls can suspend while evaluating their arguments. Source methods retain the selected receiver across suspension. A mutable reference binds its original named slot, including when a nested call writes to that slot. Async producers continue to take owned values. The ordinary binder checks reference eligibility and selects conversions.

The native fixture exercises receiver replacement during argument evaluation, an empty receiver that fails before either child starts, nested reference writes, a mutating hash method and string repetition. Incremental and fresh builds agree in PHP, C++ and JS. Deleting the child fails preparation and restoring its edited body rebuilds one native object per flavor. Passing a literal to the mutable reference parameter fails preparation.

**Run 6 complete.** The shared value-task recipe starts with inactive payload storage. A successful return move-constructs the result into the promise. The frame destroys the stored instance, including after the result moves to its consumer. Source construction may throw. Native delivery requires nonthrowing move construction and destruction. Inline record parameters and results now share the same admission check, including records with required constructor arguments.

The frame-boundary fixture uses a move-only payload with a required constructor and deleted assignment. Abandoning an unstarted task and propagating a failed child through a parent each produce zero payload constructions and destructions. A successful nested await followed by blocking extraction balances every native construction with a destruction and releases the transferred resource once. Runtime, frame-boundary and header-isolation tests pass. Incremental and fresh native programs agree for PHP, C++ and JS through a record layout edit, deletion, recovery and addition of a required constructor. A body-only edit and restoration after deletion each rebuild one object per flavor.

**Run 7 complete.** Application records reuse the owned-parameter and result rule for nested fields and inherited storage. Layout invalidation clears the cached task binding. Public authored destructors use ordinary memberwise movement and nonthrowing cleanup. Required and optional class handles retain their existing ownership and conversion rules at the async boundary.

An inner layout edit in another source rebuilds four affected objects with grouped task methods. Removing and restoring the type, changing destructor access and switching back from an inherited layout all produce fresh-equivalent results. The throwing path destroys its nested local before the caller catches the exception. A required class result retains allocation identity, an optional result delivers null, and converting a dynamically absent result to required fails before delivery. A literal null in the same required return fails preparation.

**Run 8 complete.** Typed catch handlers can suspend on a timer or a child. Native dispatch retains the original exception across suspension. The all-flavor native fixture reassigns the catch binding, suspends and compares allocation identity after bare rethrow and explicit replacement. It also verifies unmatched propagation, sibling selection, handler-local destruction and a replacement thrown by the awaited child. Incremental and fresh builds agree. Removing the child fails preparation, and restoring its edited body rebuilds one native object per flavor.

**Run 9 complete.** A coroutine keeps the ordinary pending-exit tags and loop targets in its own scope. Protected returns construct their converted value before jumping to cleanup. Native tests observe local destruction before the finalizer and exactly one cleanup on fallthrough, continue, break, nested return and exception. Deleting an awaited child fails preparation and restoring its edited body rebuilds one native object per flavor.

**Run 10 complete.** The finalizer executes in the enclosing coroutine. It can await while an exit is pending. A finalizer throwing after suspension destroys the previously saved shared return once. Catching a nested failure inside the finalizer preserves a pending exception, while an escaping replacement reaches the caller. Numbered continue and break replay their original targets through nested finalizers. A native bounds failure bypasses a source Exception handler, runs the suspending finalizer and then reaches the caller with its original diagnostic. Fresh and retained sessions agree across all three flavors, including deletion and restoration of the child used during cleanup.

**Run 11 complete.** The integration fixture continues on its first loop iteration and returns an inline record on the next. A suspending finalizer runs on both exits, after guard destruction. The returned record requires a constructor argument and contains a heap-backed string. Successful builds preserve both fields across the child wait and finalizer. Removing the child fails both compiler sessions, and restoring an edited child changes its effect trace and rebuilds one native object per flavor.

**Run 12 complete.** The native runner verified 600 successful incremental generations and their independently built fresh programs. Two additional finalizer scenarios ran in each flavor, bringing acceptance to 606 incremental/fresh pairs. The harness checks exit status, stdout bytes, stderr and affected object counts. Preparation checks matching diagnostics on retry and fresh compilation. The three runtime/frame/header tests, ordinary exception and finally suites, and 37 affected initialization, call, expression and storage regressions passed.

For the grouped loop/owned-return fixture, native dependencies show the blocking caller has no coroutine, frame or timer header. Both producer units include coroutine support. Only the timer user includes the timer header. The grouped methods unit includes the erased frame header. Dependency checks exclude the legacy async core and thread, mutex, queue and condition-variable headers from these units.

Clang 18.1.3 on WSL2, C++23 with libc++ and `-O2`, rebuilt one child object and reused the grouped task object on recovery. The independent fresh programs built five objects each. Observed compiler and native build times for the recovery edit were 3.2 ms and 421 ms for PHP, 3.3 ms and 453 ms for C++, and 3.0 ms and 367 ms for JS. These single-run timings include host load and are recorded for comparison.
