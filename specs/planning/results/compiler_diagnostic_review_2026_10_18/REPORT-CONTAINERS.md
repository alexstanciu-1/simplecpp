## Representative invalid programs rejected before emission

Invalid vector key:

    $v vector<int> = [1];
    return $v[true];

Preparation: S2S indexed access keys require int, string or mixed.
Evidence: batch11/vector_bad_key.

Copying a noncopyable element through indexing:

    $v vector<unique<int>>;
    $p = $v[0];
    return 0;

Preparation: S2S value copy requires copyable_value.
Evidence: batch11/vector_unique_read. A foreach value-copy attempt also rejects; count, empty on the container and keyed isset observational controls pass Clang.

Cross-family boxed insertion:

    $v vector<mixed> = [];
    $d dynamic = 1;
    $v[] = $d;
    return 0;

Preparation: S2S mixed/dynamic family conversion requires an explicit scalar/null cast without storage modifiers.
Evidence: batch14/vector_mixed_dynamic. The reverse insertion direction also rejects.

Unsupported operator combination:

    $v mixed = 1;
    $n = $v % 1.5;
    return 0;

Preparation: S2S boxed remainder requires boxed or ordinary int operands.
Evidence: batch12/mixed_mod_float.

Implicit incompatible scalar conversion:

    $n int = '1';
    return 0;

Preparation: S2S value boundary requires matching types or an integer conversion.
Evidence: batch11/int_string_assign.

These are rejection controls, not newly discovered gaps.

## Successful operation controls

Non-default-constructible struct payloads work through vector construction, indexing replacement, append, hash writes/reads, nested vector/hash writes and foreach:

    struct S {
        int $n;
        function __construct(int $n) { $this->n = $n; }
    }
    $v vector<S> = [new S(1)];
    $v[0] = new S(2);
    return 0;

Evidence: batch11/vector_nodefault_write and related cases; batch12/nested_nodefault, nested_hash_nodefault, foreach_nodefault. The suspected hidden requirement for default construction did not reproduce.

Other emitted controls include:
- Vector/hash payloads using value<Class>, nullable records, enum values and callable Results.
- Same-family mixed element writes and mixed keys at typed read/probe/removal boundaries.
- Nested removal/probes around noncopyable unique payloads, without copying those payloads.
- Element-level shared derived-to-base conversion; incompatible whole-container conversion rejects.
- Indexed canonical-int compound assignment, nested compound assignment and hash string concatenation assignment.
- Result container extraction, Result callable conditions/coalescing, nullable record extraction/selection, shared-handle null comparison.
- Accepted fixed-width integer arithmetic/conversions and mixed/dynamic arithmetic, logic, concatenation and updates from the sampled matrix.

## Matrix scope and limitations

cases13.json was generated by make13.py: int8, uint64, float, bool, mixed, dynamic, nullable<int>, result<int>, and string values against selected same-type binary/unary/update operators, plus implicit scalar destination types. This is not the Cartesian product of all types and operators. It does not test every operand order, mixed-width pair, runtime payload state or conversion value range.

No runtime execution means no claims about bounds handling, numeric overflow, COW semantics, evaluation order, missing-key behavior or value-dependent conversion failures. Clang compilation cannot establish those properties. Headers are checked as dependencies of emitted translation units, not forced instantiated independently.

All sources, preparation markers, encoded/materialized generated C++, outcomes and command logs are retained under batch11, batch12, batch13 and batch14. Per-case result.json identifies the failure stage; each batch has summary.json and logs/commands.json.
