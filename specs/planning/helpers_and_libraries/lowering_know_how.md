# How compiler lowering choices affect Clang and LLVM

Doc Status: planning

## Question and ownership

For each action our compiler takes, which legal C++ spelling costs least to produce, to compile and to execute? These costs can move independently. Longer generated code can simplify our emitter, make sequencing explicit or expose a fact to LLVM. Record generated bytes alongside the costs they might explain. Source semantics govern eligibility. This note collects observations and open questions for v0.2.

| Decision | Responsible layer |
| --- | --- |
| Meaning of a flavor operation, passing and result semantics, failure and evaluation guarantees | Language and library contracts. Runtime metadata records the typed operation, supported native form, parameter modes, result adaptation and declaration provider. Prefer a small set of understood forms such as a free call or member call. |
| Operand snapshot, borrow, sequencing, block placement and cleanup at this site | Compiler preparation and lowering use the resolved operation and surrounding expression. The same descriptor can be used at sites with different lifetime requirements. |
| Public declarations, inline bodies, compiled implementation and direct header dependencies | Runtime and API generator. Each unit collects the providers its lowering uses. Measure the transitive closure, including unrelated flavor headers and runtime internals. |
| Choice among eligible implementations | Keep measurements here with the toolchain and workload. Review compile and execution results separately before changing a default. |

## How to add a finding

Record the compiler action and source contract, two concrete C++ spellings, the single changed variable, host/target, Clang version, flags, runtime publication and reproduction command. Include an input that could reveal an invalid transformation, such as an aliased reference, failing conversion or a hit at offset zero. Distinguish a measured observation, its possible explanation and any proposed emitter rule.

Use a focused probe to inspect unoptimized and optimized IR and final assembly or object text. Record surviving calls, copies, cleanup and allocations when relevant. Compare machine code with a direct native or hand-LLVM baseline under the same ABI when judging execution overhead. Capturing identical instructions can settle a local code-generation question without a runtime timing claim.

Use matched builds to measure our compiler, Clang frontend, LLVM optimization, machine code generation, linking and invocation through executable. Collect traces separately from ordinary shuffled timings. For include changes record transitive headers and preprocessed bytes. For executed paths record workload CPU and allocation counts. Link raw samples and include spread when small differences matter. The access-log rewrites ran after our compiler emitted the baseline. Measuring a saving inside our own lowering requires implementing or instrumenting that action in a probe. The local scalar experiment times only the native compilation.

## Call staging in the three 100 KB pilots

A temporary observer around the C++ emitter's `value()` recorded each call or construction node, its source token range, immediate AST parent, and the expression returned for that node. Each of the 1,944 ranges occurred once within its sample. All three application units matched the previously benchmarked C++ byte for byte. Count the outer form of each source invocation once, including constructors (5 / 6 / 7 in table order) and collection cardinality calls. Operator, indexing, cleanup and other compiler-synthesized calls are outside this denominator. Counts describe static sites. [Counts by callee and source context](call_forms_100k.tsv)

| Sample | Direct, statement | Direct, value | Scoped block for call setup | Lambda, statement | Lambda, value | All sites |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Access-log | 5 | 32 | 0 | 639 | 11 | 687 |
| Stock-ledger | 4 | 38 | 0 | 574 | 9 | 625 |
| Route-table | 3 | 60 | 0 | 560 | 9 | 632 |
| Total | 12 | 130 | 0 | 1,773 | 29 | 1,944 |

“Value” includes conditions, assignments, nested expressions and echo items. For example, stock-ledger has six call lambdas underneath logical negation, two in local initializers, and one on the right of a compound update. Counting all emitted immediately invoked lambdas would also pick up 444 / 164 / 274 other lambdas respectively, primarily binary operand staging.

**Where the choice happens.** A standalone call statement requests its value expression and appends a semicolon. That path has no synchronous call-specific block form. Ordinary invocation can emit a direct call for zero or one argument, reorderable trivial values, or a call with at most one order-sensitive argument under the emitter's other eligibility checks. In the fallback it binds selected operands, moves owning values and wraps the sequence in an immediately invoked lambda. Runtime calls also have their own paths for receivers, one argument and multiple operands. For example, access-log emits `str_starts_with` directly three times and stages it four times for a checked field and a literal. Direct emission still applies any required conversions and parameter construction. [Statement emission](../../../compiler/05_backend/cpp/emit.php#L1328) · [Runtime operand selection](../../../compiler/05_backend/cpp/emit.php#L2617) · [Ordinary call selection and staging](../../../compiler/05_backend/cpp/emit.php#L2949)

| Argument shape among staged calls | Access-log | Stock-ledger | Route-table | Semantic question |
| --- | ---: | ---: | ---: | --- |
| `observe(book, literal key, event field)` | 601 | 537 | 516 | The key is passed by value and the field read checks its owner. Preserve their failure order. |
| Report dispatch with two local owners | 31 | 33 | 31 | Both operands are stable local handles. Their by-value parameters must retain ownership. |
| Other calls whose emitted snapshots are exclusively copies of local owners | 7 | 9 | 10 | Inspect the remaining inline operands and any reference bindings before dropping sequencing. |
| Other staged calls | 11 | 4 | 12 | Includes string copies, runtime borrows, literal construction and checked field reads. |
| Total | 650 | 583 | 569 | |

**Where sequencing matters.** Of the 1,654 observation keys, 577 / 532 / 504 exceed the runtime's 22-byte inline capacity. At those 1,613 sites construction can allocate before the checked event dereference. A plain C++ call can reverse these operations. Preserve that order, or prove that a competing failure is impossible at this site. A named temporary for every argument is a stronger requirement than that ordering alone. The remaining 41 keys fit inline. Extending a direct-call rule to them would require accounting for literal construction and ownership under the actual runtime contract. [String construction](../../../tools/api_generator/templates/strings/string_storage.cpp.tpl) · [Source call evaluation](../../../specs/compiler_entry_v0_2.md#explicit-mutable-reference-parameters)

**Where explicit snapshots can go away.** The 95 two-owner dispatch calls pass stable locals with no mutating or throwing sibling expressions. The generated owner copy constructor is `noexcept` and retains the existing owner. A direct by-value call still performs the parameter copies. A separate probe changed only those 95 sites to direct calls. For the 26 other owner-only staging sites the argument lists vary. Route-table's `parse_case(fields, request)` binds a stable reference and copies a local owner; stock-ledger's two `removal_cost` calls stage the same owner but have different scalar expressions. A family-wide direct-call rule needs to examine those other arguments. [Route-table source](../../../samples/single-file-pilots/scaled/100k/route-table/main.php#L170) · [Stock-ledger source](../../../samples/single-file-pilots/scaled/100k/stock-ledger/main.php#L191)

**Where a narrower proof helps.** Access-log's `percentage(report->server_errors, report->accepted)` checks the same stable owner twice and reads two scalar fields. Neither operand writes. That is a stronger basis for simplifying staging than knowing only that both operands are field reads. Its `str_starts_with(record->path, "/api/")` has a different issue: the runtime borrows strings, yet the emitter copies the field into an owning local. Route-table's `substr(path, 0, strlen(path) - 1)` snapshots the path while the later argument only reads it. Candidates for borrowing still need the same checked access, lifetime and conversion behavior. [Runtime case selection](../../../compiler/05_backend/cpp/emit.php#L2655)

**Validation and limits.** A temporary rewrite replaced every one of the 1,773 standalone call lambdas with a compound statement while preserving each declaration, checked read, move and final call in order. All three applications compiled with local Clang 18 at `-O2 -g0` and matched the complete small and full expected reports. The independent direct-call probe for the 95 report dispatches also matched the three full reports. The 29 value-position lambdas need expression-local reasoning, especially in conditions, short-circuit expressions and compound updates. These counts and functional checks give no new timing estimate. No production emitter rule was changed.

### Access-log execution profile after the scoped-block change

On dev002, 12 shuffled rounds pinned to CPU 8 reproduced the shared-workload increase. Previous and scoped-block median process times were 0.6803 and 0.7006 ms/pass (3.0% ratio of medians, 2.6% median of paired differences, slower in 12/12 pairs). Full workload medians were 4.031 and 4.098 ms/pass. The emitted C++ matched the previously measured compiler outputs by SHA-256. Old and new applications and both hybrid applications passed the full and shared expected-output checks.

**Where the change occurs.** Recompile the old application with only the body of `process_input_` taken from the new unit: 0.6941 ms shared, slower in 11/12 pairs against old. Keep the old loop and switch the rest of the translation unit to blocks: 0.6807 ms, slower in 5/12 pairs. Changes to this loop account for much of the difference at the original link layout. Each hybrid was optimized and linked as a whole application, so timings also include its layout effects.

**CPU sampling.** The benchmark account had no perf executable and a perf-event paranoid setting of 4. A separate run used a process CPU interval timer at 1 ms and sampled the interrupted instruction pointer in four fresh processes per version, 5,000 shared passes per process. Resolve sampled PCs against executable and shared-object load biases and ELF symbols. These are flat user-space profiles. About a quarter of samples landed in unnamed libc code. Old / scoped-block sample shares included byte-string construction 9.73 / 9.09%, string copy construction 6.52 / 7.89%, malloc 6.67 / 6.84%, free 3.66 / 4.55%, and the input loop itself 2.05 / 2.00%. Separate link-wrapped counts per shared pass were identical: 9,476 string copies and 16,006 pointer-and-length constructions at wrapped calls, plus 12,697 scalar allocations requesting 871,200 bytes. Differences in sample shares alone do not establish additional calls.

**Optimized LLVM and x86-64 code.** The old `process_input_` contains seven more pairs of 16-byte `llvm.lifetime.start/end` intrinsics for the native by-value owner arguments to `record_request`, `count_response`, `count_route` and `render_traffic`. These are argument objects, distinct from the source locals. The same seven objects survive as allocas in the scoped-block IR. Both versions contain 37 invokes, the same static call-target counts apart from lifetime intrinsics, 534 machine instructions and 90 machine calls. The stack allocation in the prologue changes from `sub $0x128,%rsp` to `sub $0x198,%rsp`. The record argument to both hot count calls used `0x18(%rsp)` previously. Blocks use `0x100(%rsp)` for count_response and `0xe0(%rsp)` for count_route. The loop's code grows from 2,297 to 2,345 bytes. The optimized IR instruction/call shapes and disassembly of decode_access, decimal_field, count_response and count_route show no comparable change; linked addresses and local literal labels can differ. Runtime string operations come from the same prebuilt archive.

**Causal controls.** Removing only those 14 intrinsics from the previous optimized LLVM and running codegen reproduced the entire 112-byte stack growth. Replaying unedited optimized IR reproduced the corresponding original application object’s .text bytes for both binaries. At default alignment the previous-IR control took 0.6755 ms/pass; removing the markers took 0.6871 ms (+1.7%). The interventions below inserted unexecuted text before the application object and relinked. Each cell is a median over ten shuffled processes of 160 shared passes. Time is in ms/pass.

### Restoring owner argument slot reuse inside process_input

Five access-log builds on tf-dev002 used Clang 18.1.3, libc++, mold and ordinary `-O2 -g0`. The historical lambda compiler and the current block compiler are controls. Each candidate changes four or fewer call sites in the current application unit. The direct control passes the original local owners by value at the four sites. The two forwarding variants keep the scoped declarations and moves, then send the staged arguments through one application-local template:

```cpp
template<auto Callee, class... Args>
static inline void forward_owner_args(Args&&... args) {
    Callee(static_cast<Args&&>(args)...);
}
```

The call site changes from `count_response_(...)` to `forward_owner_args<count_response_>(...)`. A forwarded owner rvalue still moves into the existing by-value ABI. The histogram lvalue remains a reference. The two-site variant covers count_response and count_route. The four-site variant also covers record_request and render_traffic. These four sites have seven by-value owner arguments between them. The other report calls and runtime headers stay as previously emitted.

### Owner forwarding in stock-ledger and route-table

This probe keeps the existing statement block and owner moves. A site qualifies for this experiment when it calls a statically named application function, all staged declarations copy by-value owners from named local handles, and every other supplied native operand is already a plain local. The other locals can be scalar values or stable reference arguments; the forwarder preserves their value categories. A staged string, checked field expression or expression-position invocation falls outside this tested shape. This distinction excludes the `observe` leaves and route-table's mixed `diagnostic` calls. No change to the 95 direct-call experiment or the production compiler is involved.

## What survives a call to strlen

Local x86-64 Clang 18.1.3, libc++, mold, ordinary `-O2 -g0`, separately compiled matching runtime, no LTO. The PHP-flavor function `function byte_len(string &$s): int { return strlen($s); }` borrows an existing string. The emitter produces `return scpp::str::byte_length(var_s_0);`. Its public inline wrapper calls `value.size()`. Optimized LLVM in the caller contains one tail call to `scpp::string::size() const` and returns its i64 result. The linked caller contains a single jump to that accessor. Its short-string path loads the tag byte, compares it with the 22-byte inline capacity, and returns the tag as the byte count. The long path follows the storage pointer, obtains the stored libc++ length, and preserves the checked signed conversion. Neither normal path scans payload bytes or allocates.

The executable printed `0 3 32` for an empty string, an embedded-NUL three-byte string and a 32-byte string. Recompiling the same emitted unit after substituting `return var_s_0.size();` produced identical application object .text bytes. For this borrowed caller, direct member syntax alone buys no machine-code improvement. This observation concerns code generation; no execution-time claim was measured. ## Open comparisons

1. **Calls and sequencing.** Extend the three-sample census with focused nested-expression and reference-return fixtures. Compare equivalent spellings at sites requiring left-to-right snapshots. Exercise aliasing, cleanup on failure, mutable output and returned references with `str_replace`, `bump` and `select`.
2. **Accessor and literal boundaries.** Compare an out-of-line accessor, narrow inline operation and compiled helper for `strlen`, literal equality and `str_starts_with`. Check short and long storage, actual public includes, frontend cost and final loads/calls.
3. **Result adaptation.** For PHP `strpos`, compare check-immediately and return-the-result callers on misses and hits including zero. Keep search and carrier representation fixed when testing only the adapter boundary. Match ABI when comparing with hand LLVM.
4. **When extra C++ pays.** Pair a simpler emitter that writes explicit steps with a more selective emitter that elides them. Measure PHP lowering time as well as native compilation, first in a focused probe and then on one of the single-file samples. Keep neutral results, regressions and version-dependent outcomes alongside wins.
5. **Stage 2, checked vector arguments.** In `preg_grep($pattern, preg_split(...))`, the typed split removes per-element boxing. The checked `.value()` still returns an owning vector by value and copies its storage before grep borrows it. Compare safe borrowing or moving for temporary and named carriers, including failure and operand lifetimes, before changing extraction.

## PHP regex capture record allocations

On dev002 with Clang 18.1.3, libc++ and `-O2`, both native offset records
measured 32 bytes. Appending 64 one-byte nullable-offset captures into a
reserved vector took zero ordinary C++ allocations. Reading all 64 byte offsets
also took zero. Reading all 64 present `?string` fields took 64 allocations.
The record stores an owning string and uses offset `-1` to represent absence.
The nullable carrier is constructed when the field is read.

For 64 hits of `/(.)/` in numbered pattern order (128 one-byte cells),
the unflagged, offset-only, null-only and combined calls made 15, 16, 144 and
16 ordinary C++ allocations respectively. These counts include output vector
growth. PCRE2 allocator traffic and long-string payloads are outside the
measurement. Reproduce with the regex module enabled and
