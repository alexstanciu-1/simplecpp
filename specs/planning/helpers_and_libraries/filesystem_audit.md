# Filesystem family audit

Doc Status: planning

Reviewed v0.2 at `8ea9c87a6`, release v0.1 at `d2f63e37e` and my-try at `624ab8a2d`. The PHP read pilot is separate at `7936b9bec`. This is a proposed implementation boundary for review.

**Count by operation.** My-try publishes 35 filesystem callables. They comprise 19 ordinary path/file operations (including the target-host query), one checked snapshot, four lock operations and eleven compiler publication operations. v0.2 ships four of the ordinary operations and adds its own staging operation. v0.1 strict maps 23 general filesystem names, including the snapshot and three locks. My-try adds the empty-lock factory. The legacy PHP surface supplies 18 natural filesystem names, and release JSS maps 18 dotted aliases. The aliases describe additional ways to call the same operations. The implemented Stage 1 contracts are recorded in the [filesystem module specification](../../filesystem_module.md). The audit below preserves the donor comparison and original proposal.

## Proposed family goal

Deliver the general path/file operations, preserve stage, and deliver the bounded PHP surface below. Include the checked snapshot as a distinct general operation with its platform contract. This gives **21 general names** (19 ordinary, stage, snapshot) and **18 proposed PHP names**. Decide the two PHP contracts called out below before creating the goal. Keep the four locks together for a dedicated resource-handle goal. Keep the eleven compiler publication functions with the publisher. The project-level opt-in and existing-caller migration belong in this first family goal. Individual performance tuning follows operational proof.

| --- | --- | --- | --- |
| `fs_get(path) → result<string>` | `file_get_contents → string or false` | `fs.get` | General shipped, PHP pilot only. Read empty, binary, missing and embedded-NUL paths. |
| `fs_put(path, data) → result<int>` | `file_put_contents → int or false` | `fs.put` | General shipped. Create/truncate, preserve binary data, return present zero for an empty write and report failed close/write. Two arguments only. |

| `fs_exists`, `fs_is_file`, `fs_is_dir`, `fs_is_link` (path → bool) | `file_exists`, `is_file`, `is_dir`, `is_link` | `fs.exists`, `fs.is_file`, `fs.is_dir`, `fs.is_link` | Add. | `fs_mkdir`, `fs_touch` (path → bool) | `mkdir`, `touch` | `fs.mkdir`, `fs.touch` | Add. Create one directory level; an existing directory gives false. Touch creates a missing file or updates time without truncating existing bytes. No recursive/mode/time arguments in this slice. |
| `fs_rmdir(path) → bool` | `rmdir` | `fs.rmdir` | Add a directory-only OS operation. Empty directory succeeds; a regular file, directory symlink and nonempty directory survive a failed call. |
| `fs_copy(source, dest) → bool` | `copy` | `fs.copy` | Add. Copy a file over an existing file. Cover missing source and blocked destination. |

| `fs_read_snapshot(path, expected_mtime, expected_size) → result<string>` | — | — | Add as a Linux checked read; report unsupported on other platforms. Test empty success, size/time mismatch, final symlink, raced replacement and cleanup. |

Path, directory, source, destination and data above are strings; both expected snapshot values are integers. Source value parameters can be borrowed as native `const string&` for a nonretaining call. Keep OS types and vendor headers private. Preserve the existing embedded-NUL rejection for OS calls, using the operation's specified false/error channel. Lexical basename/dirname operate on path bytes without touching the filesystem; specify and test their NUL handling independently. The snapshot checks identity before and after reading, caps consumption and uses whole-second timestamps. An edit preserving inode, size and timestamp can pass. ### Two PHP contracts to settle

1. **Return a typed listing from `scandir`?** I recommend `result_or_false<vector<string>>` for v0.2. Every element is a filename and the current publication already has this carrier. Release PHP returned a falseable packed mixed hash with direct wrapper iteration. A source fixture should check presence, extract the vector, and iterate in sorted order. Adopting the typed result is a source contract change from the donor. [Release scandir](../../../v0.1/specs/builtins/filesystem/scandir.md) · [Carrier contracts](../../carrier_slice.md)
2. **Should PHP `unlink` reject directories?** I recommend yes. Keep general `fs_remove` as entry removal. Use a file/link-only native operation for `unlink` and a directory-only operation for `rmdir`. A kind check followed by general remove has a race if the entry is replaced. The pinned release delegated both names to general removal; my-try subsequently corrected `rmdir`. The release unlink contract explicitly describes entry removal, so the PHP decision needs to be recorded. [Release unlink](../../../v0.1/specs/builtins/filesystem/unlink.md) · [Directory removal contract](../../../v0.1/specs/builtins/filesystem/rmdir.md)

## Publication, visibility and proof

The current filesystem generator requires an `fs_*` source key, unique native names, fixed parameter lists and published result identities. The module header contains the declarations selected for that publication. Introduce metadata for **source exposures of a native operation**. An identical contract can resolve straight to the native target. A PHP falseable result can use one small adapter calling that target once. The pilot demonstrates this for reads; its include closure and owning-string extraction still warrant review. Give the distinct unlink contract its own native target. Inspect the local pilot using `git show 7936b9bec:v0.2/specs/planning/helpers_and_libraries/pilot/README.md`. [Generator](../../../tools/api_generator/php/module_functions.php) · [Publication](../../../runtime/metadata/filesystem_publication.json)

In a fresh filesystem-enabled build with the archive absent, PHP and Python source probes calling plain `fs_get("empty")` each emitted a direct `::scpp::fs::get` call. PHP `file_get_contents` failed lookup. Temporary metadata probes confirmed three distinct cases: a PHP-style key was rejected as an invalid module function name; `result<vector<string>>` failed module type lookup while the published identity `result_vector_string` generated a descriptor for the right carrier; and `file_lock_handle` was rejected as unpublished. These probes generated descriptors only. They did not implement listing or locks.

For the goal, test module selection and general visibility independently, including rooted calls, aliases and imports, source shadowing, mixed-flavor units, and an incremental opt-in toggle against a fresh build. Migrate the nine workload manifests and the generated PHP/JS fixture manifests that use general names. Preserve the existing C++ default. Compile a one-call public header on its own, inspect generated C++ and actual includes, and exercise reduced publication. **Validation performed.** Built `scpp_filesystem`, `scpp_runtime` and `scpp_compiler_publication` in a temporary checkout of the active tree with filesystem enabled. Both `compiler_filesystem_native` and `compiler_translated_publisher_cleanup` passed on Linux. Together they exercise real generated callers for the five current operations, binary and empty data, module removal/recovery, stage cleanup, failed promotion and retry. General PHP/JS visibility in the existing fixture describes today's behavior. The new contract will need opposite default-visibility assertions. Stage 2 performance and non-Linux execution remain outside this audit.
