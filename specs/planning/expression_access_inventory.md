# Expression and access-path inventory

Doc Status: planning

Review baseline: `c0a428116`, 2026-11-28. PHP is the primary frontend. Other flavors appear where syntax, storage semantics or shared lowering change the answer. The unit of review is a semantic distinction that can change observable behavior. The original stress expression is `$something[$selector[12]->func()[10]][a_constant]($arg)`.

**How to read the columns.** “Implemented” applies to the specific shape in its row. “Open” means the exact composition needs inspection or execution. “Restricted” records an admission boundary. Native “pass” means a prior dev002 observation in this audit series. “Historical” refers to the pinned original audit. “Fixture” means a native test exists but its specific outcome was not independently verified for this inventory. Rejections can be verified at preparation without a native executable. Coverage names point to committed files under [compiler/tests](../../compiler/tests/), registered through [CMake](../../CMakeLists.txt); some full matrices are on demand. “Adjacent” means the named test covers a related shape. “Probe only” is local audit evidence outside the registered suite. No new native runs are claimed here. The latest pull adds terminal void calls in PHP nullsafe statements. The earlier 22-test dev002 run covers revision `c7267354a`; it predates that addition.

## Review queue and remaining work

1. **Awaited key lookup.** Run replacement and removal on the same holder, trace helper entry/resumption, subsequent argument and invoked function. Then move suspension into both key and argument to pinpoint callee capture.
2. **Failure and cleanup.** Throw once in the key, once in the argument after capture, once in the RHS before store. Hold only one external owner and observe cleanup. Include missing hash key versus present empty callable. Check for extra evaluation, partial mutation and stale owners.
3. **Storage and role boundaries.** Use the same expression as a value, receiver, argument and destination. Vary shared/inline, readonly/mutable and stable/temporary one at a time. Check grouped and ungrouped PHP forms and one control in each applicable other flavor. Include nested mixed reads inside a key or RHS.
4. **Branch composition and incremental recovery.** Exercise a full ternary or match returning the next receiver/callee, branch-specific failure, and cross-file signature invalidation. Prefer a discriminating witness over another permutation of an already-covered chain.
5. **Terminal void and chain boundaries.** Check the new statement/value distinction for a key, argument and additional suffix. Compare grouped and ungrouped optional receivers; track any undefined language decision separately.
6. **Protect the anchor.** Re-run the original complete PHP example on the current branch. Decide whether the entire expression merits one permanent regression alongside the smaller contracts.

**Fix list at review time.** The known nested lost write, indexed shared-holder write rejection and grouped-local/factory invocation gaps have fixes and regression evidence. No current mandatory compiler fix or normative feature omission has been demonstrated by the new open rows. Candidate diagnostic issue: the historical Python nested typed-write rejection named storage alternatives without identifying the flavor boundary; recheck current output before filing. Candidate consistency issue: whether grouping or deep-write context changes admission of an otherwise identical read; requires a current reproducer.

**Deferred or requiring a decision.** Retain the existing admission boundaries for durable references into relocatable elements, mixed nested reads and nonlocal `??=`. Confirm intended cross-flavor indexed-callee syntax and any extension to nullsafe/dynamic write syntax separately. None is approved implementation work in this review. The eventual audit should report confirmed defects, agreed-but-missing features, and intentional restrictions separately, with revision, minimal program, observed/expected effect trace and first deciding compiler stage.
