# Simple C++ v0.2 development
Doc Status: planning

## Agreed direction

Develop here on `v0.2/develop`, starting from research checkpoint
`044f6a65` (the S2S latency handoff). This is the user-authorized v0.2
integration branch, not a release-ready branch. No separate repository or
worktree is required now. See the branch exception in
[the Git workflow](../git_workflow_release_procedure.md).

At release, the new compiler replaces the current S2S path. There is one small,
user-controlled application to migrate; preserving the old implementation or
building a compatibility framework is not a release goal. Existing tests and
specs remain useful correctness evidence and current authority until deliberately
revised. Removal of compatibility work does not authorize accidental semantics.

## Goals

1. Develop the compiler in executable PHP with explicit portability annotations.
2. Build a separate PHP-written, file-to-file converter using `token_get_all()`
   and a simple structural AST. Use local annotations/library operations only,
   without symbol resolution. Incrementally convert changed files; use a small PHP
   support library for approximations and test native-only capabilities after porting.
3. Create an authoring skill from the portable profile and executable checks.
4. Adopt the complete existing compiler and required runtime-preparation/tooling
   into one development home. Preserve its native/LLVM investment and tests.
   Complete portability migration before adding compiler functionality.
5. Make S2S a compiler-owned C++ backend, simplify generated C++ using resolved
   facts, and enable deliberately specified features such as dynamic member access.
6. Implement the stable artifact/dependency architecture from the
   [technical handoff](s2s_next_generator_technical_handoff.md). Its 1.5-second
   frontend allowance is assumed, not measured; measure the integrated frontend.
7. Replace Prism branding with Simple C++ and canonical on-disk names with `scpp`.
   v0.2 still accepts legacy `.prism` and other Prism-derived file/folder names.
   New output and examples use the new names; legacy mentions belong only in
   compatibility/migration guidance. Exact mappings and coexistence rules remain
   to be specified. **v0.3: remove legacy Prism file/folder support completely.**

## Sequence

First preserve and inventory the complete compiler, establish an isolated baseline,
and adopt it here with relocation-only changes. This repository then becomes its
sole development home; the original is preserved reference, not a parallel fork.
See the [migration boundary and baseline plan](compiler_migration/README.md).

Adapt production PHP incrementally into portability-ready PHP and generated PHP++.
For each bounded component: explicit intent, PHP tests, local conversion, native
compilation/execution and consolidation. Extend portability tooling/framework only
as needed to preserve existing capabilities. Complete the full agreed migration
before adding even the new C++ backend or other compiler functionality.

After migration, develop C++ generation from shared semantic facts and the latency
handoff. Preserve and continue native preparation/lowering/LLVM toward v0.3. Do not
split the prototype into a partial compiler and an independently evolving native one.
