# Bootstrap inventory of multitype parameters and returns

Doc Status: planning

Snapshot: `cc0a9bbd7`, 20 November 2026.

Unit of count: one declared parameter or return position. The PHP token scan covered functions, methods and closures in the v0.2 compiler, with generated PHP counted separately. It excluded examples, tests and tools, skipped comments, and counted the type before a parameter name or after a return colon. Reversed arms count as the same contract. Properties, PHPDoc element types, catch clauses and arithmetic operators fall outside this inventory. Calls are verified against parameter contracts rather than counted as additional signatures.

Explicit unions and intersections account for 39 handwritten parameters and 17 handwritten returns, plus 10 generated parameters and 21 generated returns. All explicit compound parameters counted here are required and passed by value. Separately, shorthand `?T` appears on 220 handwritten parameters and 94 returns, plus 57 generated parameters and 82 returns. Those counts establish where presence occurs; native support still depends on the payload and its ownership.

### Session-owned lazy registry proof

The [runtime lookup fixture](../../compiler/tests/bootstrap_runtime_lookup_native.py) also compiles a small registry consumer in cpp, php and js. A session owns a typed hash of shared descriptors keyed by name. The resolver uses `hash_get_or_null` once, returns the cached owner on a hit, and calls the factory and inserts its result only for a recognized miss. Unknown names return an empty handle. The session owns the cache across body revisions. The descriptor stays alive independently when a caller retains its handle.

The native fixture binds `fixed(1)` and its edit `fixed(2)` in the same live session and checks shared identity. An unknown call leaves the entry count at one. A fresh session starts empty and constructs a distinct descriptor. The observable factory trace contains exactly one call per session. Separately, the resident compiler rebuilds the fixture after a factory-body edit, reuses the registry unit, and recovers from factory deletion. Each successful revision is compared with fresh emission and executed. This establishes a port shape using existing language operations. Porting the generated registry, including flavor aliases for canonical keys, remains separate.

### Fixed input records and the temporary path index

The [three-flavor proof](../../compiler/tests/input_records_native.py) covers the two fixed-shape spreads in [input capture and indexing](../../compiler/01_prepare_inputs/changes.php). A value constructor creates the saved flavor, mtime and size record. A second constructor accepts that record and the module identity and projects their fields into a flat row keyed by absolute path. The capture record stays keyed by relative path. The two sets of fields are disjoint, so ordinary constructors express the merge without an overwrite policy.

The proof feeds observed filesystem stamps to the native programs and compares every saved row and index lookup with the PHP scanner on initial capture, edit, deletion and restoration. The fixture writes its typed hash in reverse path order and reads it in sorted path order for publication. The existing PHP bundle writer persists the native source rows in the captured state and its complete manifest must match byte for byte. Filesystem traversal, canonical key sorting and JSON serialization remain host responsibilities in this proof. Sizes cover the nonnegative range supplied by PHP's signed stat integers.

### Runtime operand access during the native port

The [call node](../../compiler/03_parse/structures/functions.php) owns its written argument vector and optional receiver. [Preparation](../../compiler/04_analyze/prepare/prepare.php) uses the logical count to select an arity, reads an overload selector by index, then walks the operands. [Emission](../../compiler/05_backend/cpp/emit.php) reads operand zero separately for member bindings and walks the remaining arguments. Its capture indices and rendered C++ fragments are emitter outputs. [Host inspection](../../compiler/host/compilation.php) maps the logical sequence into report rows for both call statements and expressions. Each consumer can read the syntax in place.

The [three-flavor proof](../../compiler/tests/runtime_operand_projection_native.py) computes one signed offset per traversal. Take +1 to skip the written type marker for the resolved enum conversion, -1 to include a value receiver, and zero otherwise. The logical count is the written count minus the offset. With a prepended receiver, logical index zero reads the receiver. Every other valid index reads the written vector at index plus offset. Preparation must determine this layout before arity/overload selection, as the PHP implementation does. The offset belongs to the operation and adds no persistent AST or preparation state.

The fixture compares count, positional order and shared allocation identity against the [PHP call-node oracle](../../compiler/tests/runtime_operand_oracle.php), both with an explicit binding and after settling it. It covers empty and populated free calls, receiver-only and multi-argument member calls, a type qualifier, and enum conversion with and without a written marker. Caller edits and restoration are compared with fresh emission. This removes the need for a second operand vector in the port. Individual shared-handle reads can still retain a node temporarily. The proof does not measure timing or change the PHP compiler's lowering.

## Completion criterion

Run PHP/C++/JS source fixtures for every admitted language shape, with successful calls, rejection and fresh/incremental recovery. Include a cross-file caller and callee, return forwarding, and header/ABI updates after a declaration edit. Verify exact canonical override contracts for unions and distinct slot names when the native owner is shared. Exercise native lifetime where selected alternatives outlive the call. For generator-owned changes regenerate and compare signatures at every override. Bootstrap closure means every census row has a disposition and a proof for the actual consumer. General N-arm syntax, arbitrary heterogeneous unions, union references/defaults, variance, intersection returns, compound callback components and nested union/intersection syntax each require separate evidence and policy before becoming language goals.
