# PHP developer walkthrough for v0.2

Doc Status: planning

A PHP developer can ship a native CLI or FastCGI application with this flavor. Familiar spelling is a useful starting point. The bindings, types and failure contracts are Simple C++'s. These observations come from building PHP-flavor projects at `356b6ff15` on Linux with Clang/libc++ at `-O2`. Stock PHP comparisons used the local 64-bit PHP 8.5.7 CLI. The full matrices were also run on dev002 with PHP 8.5.12, Clang 18 and a staged libc++ SDK. The named snippets, presence, storage, paired-comparison and JSON wire observations matched the local outputs byte-for-byte. All eleven applications passed on both hosts. The linked specifications own language decisions.

For a side-by-side introduction, open the same settings-patch application in [stock PHP](../../samples/php-developer-qos/stock-php/settings-patch.php) and [Simple C++ PHP flavor](../../samples/php-developer-qos/settings-patch/main.php). Follow `{"enabled":false,"limit":0}` through validation and serialization. Then omit `limit`, and finally send `"limit":null`. The executable controls check all three meanings.

## Start here

1. Write statements directly in `main.php`. An inferred local keeps its type. Write `$limit ?int = null;` when the initializer alone cannot name the type. Named functions declare parameter and return types. Ordinary PHP function parameter spelling works, e.g. `function quote(int $cents): string`.
2. Pick the shape of your data. A `vector<string>` holds a dense list. In `hash<int,string>`, **value comes first**: it maps string keys to integers. A loose literal such as `$row = [];` puts subsequent reads in the boxed world. Materialize a typed local at the boundary where the program needs that type.
3. Both `mixed` and `dynamic` hold null, bool, integer, float, string and containers of their own family. Copy a mixed tree to edit it independently. Copies of a dynamic container share mutations. Application objects, typed collections and the other family's containers need an explicit application-level mapping to become a boxed tree. [Boxed families](../dynamic_types.md)
4. Separate three questions: did the call succeed, what kind of value came back, and is its value truthy? For `result<T>` and `result_or_false<T>`, use `isset($r)` before extracting when absence/failure is expected. A successful zero, false or null can matter. A nullable integer's `??` fallback preserves zero. See the tested guard table below before generalizing across types.
5. Select optional libraries in the root manifest's `dependencies.runtime.modules` and build the matching providers. General API names in PHP normally need the project-level `general_api` opt-in. The FastCGI application receives a request snapshot and owns its response. [Project build](../../compiler/docs/native_build.md) · [FastCGI surface](../fastcgi_module.md)

## What presence actually tested

The [presence experiment](../../samples/php-developer-qos/presence.py) builds each operation separately: 37 inputs across 11 static type/API cases and six expressions, for 222 builds. The table shows the four guard expressions. The driver also records emptiness and coalescing. In each cell, outcomes follow the input order in column two. Y/N are the boolean results; **R** is a runtime failure; **B** is a build rejection. A plain condition on a wrapper may test its payload. For example, a successful search at byte zero is present and falsey. With `result_or_false<bool>`, assigning `false` produced a present false payload and assigning `false_sentinel` produced absence. Reversing the operands of the literal-false test on a missed search still failed at runtime.

| Value | Inputs in order | `isset($v)` | `if ($v)` | `$v === false` | `$v === null` |
| --- | --- | --- | --- | --- | --- |
| `?int` / nullable hash lookup | 0, 2, absent | Y Y N | N Y N | N N R | N N Y |
| `?bool` | false, true, absent | Y Y N | N Y N | Y N R | N N Y |
| `?string` | empty, text, absent | Y Y N | N Y N | N N R | N N Y |
| `result_or_bool<bool>` | false payload, true payload, false sentinel, true sentinel | Y Y N Y | N Y N Y | Y N R R | N N R R |
| `strpos` | offset 0, offset 2, miss | Y Y N | N Y N | N N R | N N R |
| `getenv` | empty, nonempty, missing | Y Y N | N Y N | N N R | N N R |
| `json_decode_mixed` result | JSON false, JSON null, malformed | Y Y N | B B B | B B B | B B B |
| Raw `mixed` / `dynamic` | false, 0, empty string, null, empty container | all B | all B | all B | N N N Y N |
| `?User` | live object, absent | B B | Y N | B B | N Y |

A missed search exposes a migration trap in both directions. With identical source, `$p=strpos("abc","x"); echo isset($p)?"present":"absent";`, stock PHP printed `present` because its ordinary false value is set. Simple C++ printed `absent` because the return carries a false sentinel. For `result_or_bool<bool>`, the true sentinel also passed `isset` even though it cannot supply a payload. Choose the guard for the actual return contract.

On the native path, the search guard `$p !== false` evaluated `(var_p_1).value()` and then returned a constant true for the strict int/bool mismatch. The [SQL example](../../samples/php-developer-qos/ticket-report/query-states.php) lowered its two literal comparisons to `.is_false()` and `.is_true()`. A failed query, an UPDATE matching zero rows and a SELECT returned `error`, `command` and `count 6` respectively. Run `snippets.py --show strict-sentinel-miss true-status-is-set` to inspect the minimal source for both failure modes. The PHP frontend’s special case for literal boolean sentinels requires a runtime-handle payload. The scalar branch falls through to extraction. [Semantic preparation](../../compiler/04_analyze/prepare/prepare.php#L1656) · [Carrier lowering](../../compiler/types/carrier.php#L37)

## Findings by developer task

The following 33 tasks group related expressions under the decision a developer has to make. Each row gives the observed behavior and a working approach. Links to contracts distinguish deliberate semantics from gaps in the current PHP frontend.

## Differential controls and developer build loop

- The [stock PHP comparison](../../samples/php-developer-qos/compare_php.py) exercised eleven operations on files containing empty text, decimal-looking strings, whitespace, embedded NUL, UTF-8, decomposed characters and invalid UTF-8. **237 of 241 outputs matched**. Twenty additional identical-source stock PHP controls checked accepted syntax and output. Truth, byte length/trim/lower/slice, prefix detection, splitting, replacement count and search position matched throughout their sampled inputs. All four differences were numeric-looking string equality or ordering. The search control deliberately used each language's correct miss check to isolate the byte search.
- A fresh active-source archive, without generated build products, ran the README queue-report command successfully. Building the catalog with its JSON manifest immediately afterward reported a missing `runtime-boxed` archive with “Build the dependency before building the application.” Enabling `SCPP_ENABLE_JSON`, building `scpp_json` and the filesystem provider, then retrying successfully built the catalog. After a successful build, turning JSON off and rebuilding the filesystem provider left the old JSON archive on disk. Both reused and fresh application build directories then rejected the catalog at its `json_node` parameter. The diagnostic said “Unknown or unsupported parameter type” although the manifest still selected JSON. Both setup failures could name the requested module and its CMake target.
- The [edit cycle](../../samples/php-developer-qos/edit_cycle.py) changed a helper's literal from 200 to 404 with the same length and two distinct subsecond mtimes in the same second. The normal build succeeded and the executable still printed 200. Ordinary write/build/write/build trials, **without setting timestamps**, reproduced stale output five out of five on each host: 247–255 ms between writes locally on the final pass, 161–187 ms on dev002. This matches the documented second-resolution source fingerprint. `project ... --force` followed by `build` recovered the edit. A different-length invalid edit returned a source file, line and column; repairing it produced 201 on the next build. An editor-style atomic replacement changed the inode and replaced `echo 404` with the equally long, invalid `echo @@@` in the same timestamp second. Both hosts reported a successful build and still printed 404. Forced preparation rejected the source at line 1, column 6. After a reported build failure, the previous good executable remained on disk. The ordinary-save control is reproducible with `edit_cycle.py --ordinary-saves`. - A project folder containing spaces without an explicit module name failed with “Invalid module name” because the folder basename becomes the default identity. Providing a valid manifest name built successfully in the same path.
- The [project layout experiment](../../samples/php-developer-qos/project_layout.py) discovered a helper under `src/` automatically. Adding an ordinary PHP control file under `tests/` broke the build at its opening tag. Giving tests its own module root or explicitly selecting the app sources restored the build. Moving an explicitly named helper reported its old path; updating the manifest recovered. Eight filesystem configuration cases confirmed that the PHP alias needs the module, and the general name needs both the module and opt-in. With the name invisible, the diagnostic was “Unknown function”. With the name visible but the module missing, it named the module.

## What to address first

1. **Make the edit/build/run result trustworthy.** The incremental builder can report success and leave the previous literal in the executable after a real save. The acceptance test is two equal-size edits within one timestamp second followed by an ordinary build and execution of the second value. Keep the no-change reuse case too.
2. **Align comparisons with the carrier contract.** Start with two same-typed operands where the state rule is specified. Cover both absent, one absent, and present zero/false. Review the literal-false PHP surface explicitly alongside that work. A new user should be able to evaluate the guard itself on both a hit and a miss.
3. **Make the typed boundary discoverable at the error site.** Focus on exact builtin arguments, boxed predicates, nullable fields and generic declarations. Each already has a runnable example of a rejected expression and a small working rewrite. Keep the error position and include the received type, supported form, or missing provider when known.
4. **Choose the first PHP web conveniences based on application code.** Flat form/query decoding and context-specific HTML escaping have concrete callers here. Decide the input domain, malformed-input policy and output context first. Byte search, number formatting, typed traversal, stream append and database parameter execution already support practical paths.

The evidence covers Linux native programs, a private MariaDB, FastCGI/Apache and selected stock PHP controls. The owning specs and focused regression suites remain the places to decide and enforce a language change.
